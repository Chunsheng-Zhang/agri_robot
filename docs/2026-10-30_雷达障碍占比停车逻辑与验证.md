# 雷达障碍占比停车逻辑与验证

日期：2026-10-30（Asia/Shanghai）。本次不启动实车运动，不解除急停，不恢复任务。

## 用户要求与现行判据

用户要求取消“至少 50% 射线有有效回波才允许运动”的条件，默认接收到的扫描可用；仅统计停车范围内的有效障碍回波占比来停车。用户明确选择 2% 门槛。

```text
障碍占比 = 停车净空区域内的有效障碍点数 / 检测角度内的全部扫描槽位数
停车条件 = 障碍占比 >= 0.02
```

当前配置仅检测车头前方 ±90°，约 1010 个槽位时，20 个障碍点不足门槛，21 个达到门槛。分母包含零值、NaN、无返回和其他没有可用距离的槽位；这些槽位不贡献障碍点。不将无返回伪造成远距离点，也不再按其数量判断雷达故障。原始 `/scan` 保持不变。

“有效障碍点”指有有限、量程内距离，且经雷达安装偏移转换后落入当前运动停车区域的点。前进沿用车体走廊，转向沿用旋转包络；既前进又转向时取区域并集，同一回波只计一次。停车净空沿用 0.8 m，按车体净空计算，不是单纯以雷达为中心的 0.8 m 圆。因此前方约 1.5 m 的目标不应触发停车。

用户已接受：正常导航和转向不要求后方有效，后方、侧后方没有雷达保护。比例判断也意味着小于 2% 的细小障碍可能不停车；没有据此验证对所有尺寸障碍可靠停车。

仍保留数据通道检查：话题应及时更新、发布者唯一、时间戳新鲜、坐标系和扫描几何结构正确，扫描超时仍为 0.5 s。完全没有回波但持续收到正常结构的新扫描可用；完全收不到扫描会停车。独立急停、手柄断联、控制权、指令超时、定位约束继续生效。

停车后不会自行恢复。保留较大的 1.2 m 恢复净空区，要求该区域障碍占比低于 2% 持续 1 s，然后允许人工解除障碍锁定；任务继续/手动接管仍需明确操作。只有离开 0.8 m 区域、但仍在 1.2 m 区域且占比达到门槛时，不允许解除障碍停车。

## 配置和页面

实际统一启动配置为 `config/jetson_system.yaml`，默认 ROS 配置为 `agri_robot_ws/src/agri_bringup/config/system.yaml`。两者均使用：

```yaml
safety:
  ros__parameters:
    require_lidar: false
    lidar_front_only: true
    obstacle_fraction: 0.02
    stop_distance: 0.8
    resume_distance: 1.2
    clear_duration: 1.0
```

`require_lidar: false` 仍是以后统一启动的初始约定，不改变用户当前 Web 中已经开启的保护。`obstacle_fraction` 为只读物理配置，改变后需在停车时重载核心。旧 `min_valid_fraction` 已从当前实现和两份活动配置中移除。

Web 安全状态显示停车区域占比、障碍点数/全部槽位、当前 2% 门槛。`/safety/status.obstacle_fraction` 报告实际参数；`/safety/obstacles` 增加 `total_beams`、`stop_points`、`stop_fraction`、`resume_points`、`resume_fraction`。无距离回波时最近距离为空，不伪造为零米。
