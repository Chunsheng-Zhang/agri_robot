## 1. 本轮做了什么

在室外让车辆从当前位置依次到达五个默认航点，使用 MGX23 位姿和独立多点导航控制器。最高前向速度指令按用户要求设为 0.5 m/s，接近目标时减速，必要时停车旋转对齐，每点停留 2 s。按用户此前的明确要求，本轮雷达驱动及雷达障碍停车联锁关闭，其他急停、手柄断联、指令超时及自主定位检查保留。

最终任务状态为 COMPLETED，五点依次完成，任务用时 140.490 s。结束后软件急停重新锁定，控制权释放，控制输出为零；另外采集的 7 条底盘反馈也均为零。录包正常结束，核心和前后端在本轮结束时保留运行、车辆待命。

## 3. 命令记录的表示方法与公共环境

本轮大量操作由 Python subprocess 启动进程，使用 Python HTTP 客户端调用后端，并通过 ROS 服务确认停止。下文把相同参数整理成便于阅读的终端形式；不是声称每个代码块都曾原样粘贴到终端执行。四个主要进程的真实参数数组保存在 RUN/processes.json。

例如，本轮进程把输出追加写入 RUN/core.log；下面使用重定向表示这一行为，实际是 subprocess 的 stdout/stderr 文件句柄。环境变量 RUN、WEB_RUN 是文档中对实际绝对路径的简称。

~~~bash
cd /home/jetson/agri_robot
source scripts/setup_environment.bash

export RUN=/home/jetson/agri_robot/data/experiments/20261029_outdoor_waypoint_lHbQGV
export WEB_RUN=/home/jetson/agri_robot/data/experiments/20261029_135713_042628_web_496dd246
export TMPDIR=/home/jetson/agri_robot/.runtime/tmp
export ROS_LOG_DIR="$RUN/ros_logs"
export AGRI_SYSTEM_CONFIG="$RUN/system.yaml"
export PYTHONDONTWRITEBYTECODE=1
~~~

其中 AGRI_SYSTEM_CONFIG 使后端使用与核心一致的配置副本。TMPDIR、ROS_LOG_DIR 将本次启动临时文件和 ROS 日志放在工作区内；禁止写 Python 字节码用于避免导入时向工作区外的已安装包写缓存。

本轮实验目录的创建命令是：


本次得到的随机后缀是 lHbQGV。另建立 raw、ros_logs、safety、checks、bag 子目录，并将统一配置复制为 RUN/system.yaml 后调整本轮参数。不要重新对本次 bag/core 执行录制，它已经存在并已关闭。

## 4. 正式运动前的检查和处理

### 4.1 核对并停止独立原厂进程

检查了进程、监听端口、设备节点、/vel_raw、/joy、/voltage 以及 /cmd_vel 的发布者。主要检查命令为：

~~~bash
ps -eo pid,ppid,comm,args
ss -ltnp
~~~

ROS 只读诊断通过 Python rclpy 节点订阅话题完成。首次采样发现：

| 检查 | 实际结果 |
| --- | --- |
| 独立底盘 | ros2 run yahboomcar_bringup Mcnamu_driver_X3，直接使用原 cmd_vel 输入 |
| 独立手柄逻辑 | ros2 run yahboomcar_ctrl yahboom_joy_X3；joy_ctrl 在发布 /cmd_vel |
| 原始手柄节点 | ros2 run joy joy_node |
| 底盘反馈 | 三个平面速度分量均为 0 |
| 手柄状态 | 摇杆中立，按钮未按下，8 个 axes、15 个 buttons |
| 电压 | 约 11.9 V |
| 统一核心与后端 | 尚未运行 |

处理顺序为：确认零速 → SIGINT 停止独立原厂手柄逻辑 → 通过临时 ROS 节点向 /cmd_vel 只发零速度约 1.5 s → SIGINT 停止独立底盘和 joy 节点 → 再启动统一核心。

停止信号由 Python os.kill(pid, signal.SIGINT) 发送；发送前逐一检查了 /proc/PID/cmdline。这里不提供可直接复用的历史 PID 杀进程命令，避免以后 PID 重用时误停其他进程。该阶段没有直接发布非零底盘运动命令。

## 5. 实际启动了哪些程序

### 5.1 ROS 统一核心

最终使用的命令参数为：

~~~bash
cd /home/jetson/agri_robot
source scripts/setup_environment.bash
bash scripts/start_core.bash \
  mode:=base \
  chassis:=yahboom_x3 \
  params_file:="$RUN/system.yaml" \
  rosmaster_pythonpath:=/home/jetson/agri_robot/robot_sim/src \
  start_mgx23:=true \
  start_joy:=true \
  start_lidar:=false \
  require_lidar:=false \
  start_camera:=true \
  start_video:=true \
  start_planner:=false \
  event_directory:="$RUN/safety" \
  >> "$RUN/core.log" 2>&1
~~~

说明：启动参数 mode:=base 选择初始基础待命；程序启动后另通过正式模式服务切到 waypoint。start_lidar:=false 停用驱动，require_lidar:=false 停用雷达障碍/超时停车联锁；急停等其他检查保留。start_planner:=false 只关闭覆盖规划模块，多点导航独立运行。

此命令实际启动 localization、safety、chassis_adapter、joy_node、joy_adapter、sensor_frames、Astra 相机、camera_status、web_video_server、mgx23_node、原厂 Mcnamu_driver_X3、waypoint、待命的 path_tracker。path_tracker 常驻但没有开始跟踪任务。

本轮核心共启动三次：首次静止准备；MGX23 驱动重建后重载；用户指定 0.5 m/s 后重载。三次使用相同命令参数和同一路径配置文件，但该副本的速度在最后一次重载前更新。录包跨越这些准备阶段，正式导航只发生在最后一次启动之后。

### 6.2 实际调用的接口

任务没有覆盖原任务文件，而是读取原任务，筛选 name、mode、waypoints、boundary、parameters 字段后创建独立副本。最初第 1 版是 0.1 m/s；运动前按用户要求更新为第 2 版 0.5 m/s。

| 顺序 | HTTP 方法与路径 | 内容 / 结果 |
| --- | --- | --- |
| 1 | GET /api/robot/status、GET /api/devices | 多次检查位置、航向、数据年龄、急停、手柄和零速 |
| 2 | POST /api/missions | 创建五点验证任务，获得任务 ID 5d8f0e56c581462bbb4f9f3dd79bfc46 |
| 3 | PUT /api/missions/5d8f0e56c581462bbb4f9f3dd79bfc46 | revision=1，max_linear 改为 0.5；返回 revision=2 |
| 4 | POST /api/system/mode | 请求体为 {"mode":"waypoint"}；确认切到多点导航待命 |
| 5 | POST /api/robot/emergency-stop/reset | 仅在前置检查通过后请求解除软件急停 |
| 6 | POST /api/missions/5d8f0e56c581462bbb4f9f3dd79bfc46/start | 返回 success=true、message=ACQUIRING、上述 Web 轮次 ID |
| 7 | GET /api/devices、GET /api/robot/status | 持续检查 RUNNING、目标序号、距离、控制权、定位和速度 |
| 8 | ROS /safety/emergency_stop，SetBool(data=true) | COMPLETED 后重新锁定急停，并确认服务成功 |
| 9 | GET /api/workspace | 同步任务完成及运行目录，保存到 summary.json |

上述 HTTP 请求由 Python urllib 执行，不是直接向最终 /cmd_vel 或 /base/driver_cmd_vel 发布非零速度。

### 6.3 实际执行的监控脚本

代码已保存在 [validate_run.py](../data/experiments/20261029_outdoor_waypoint_lHbQGV/validate_run.py)。正式执行时，命令为：

~~~bash
cd /home/jetson/agri_robot
source scripts/setup_environment.bash
export TMPDIR=/home/jetson/agri_robot/.runtime/tmp
export ROS_LOG_DIR="$RUN/ros_logs"

  data/experiments/20261029_outdoor_waypoint_lHbQGV/validate_run.py
~~~

该脚本会解除急停并真实开始任务，不能当作只读查看命令再次运行。它读取本轮 validation_mission.json，经后端开始这一任务，不自行生成底盘非零速度。

开始前检查：处于 waypoint 模式、无 owner、急停锁定、定位有效、手柄在线、位姿年龄小于 0.3 s、安全限速 0.5 m/s / 0.3 rad/s、雷达策略符合本轮要求。此前静态检查记录的位置离散最大约 0.003 m，但这不等于绝对定位精度。

运行时约每 0.25 s 加上请求耗时采样一次，实际 495 条记录。监控以下条件，异常即请求急停并尝试取消任务：

- 安全/任务反馈过期，定位或手柄健康丢失。
- 任务进入 FAULT、CANCELED、PAUSED，或其他控制器接管。
- 采样速度指令超过 0.501 m/s、角速度超过 0.301 rad/s，或出现非零横移。
- 到当前目标的距离连续 35 s 没有改善，或偏离当前目标连线走廊超过 1.5 m。
- 总验证时间超过 15 min，或监控脚本收到中断。

这些是本次试验监控条件，不是新增到底盘固件的硬实时保护，也不是物理障碍检测。本轮未触发这些异常终止条件。即使正常完成，脚本 finally 中仍会调用 ROS 急停服务。

index=5 是从 0 开始计数的五点任务全部完成后的值，不表示正在前往第六个点。各时间是约 5 s 一次控制台输出对应的采样时刻，不是精确的到点事件时间；更精细分析使用轨迹 CSV 和 Bag。

本次正常完成后没有再对任务执行 cancel，避免把已完成状态改写成 CANCELED。监控脚本只在异常结束分支尝试取消任务。

## 10. CSV、JSONL 字段及坐标含义

### 10.1 waypoint 轨迹 CSV

真实表头：

~~~csv
stamp,x,y,yaw,target_index,distance,heading_error
~~~

| 字段 | 含义 / 单位 |
| --- | --- |
| stamp | /odom.header.stamp，ROS 主机时间秒；不是 MGX23 原始设备时间 |
| x、y | map 基准下 base_link 位置，m；x 网格东、y 网格北 |
| yaw | ROS 航向，rad；网格东为 0，逆时针为正 |
| target_index | 当前目标索引，0 对应 target_1，4 对应 target_5 |
| distance | 当前定位位置到当前目标的平面距离，m |
| heading_error | 指向目标的方位角减当前航向，归一到 [-π,π]，rad |

轨迹按控制循环尝试记录，但相同 /odom 时间戳不重复写入。本轮 1402 条对应实际位姿更新，不能仅凭 control_rate=20 就假定 CSV 一定每秒 20 行。CSV 正常关闭，同名 JSON 必须一起保留。

### 10.2 速度导出 CSV

真实表头：

~~~csv
topic,elapsed_s,linear_x,linear_y,angular_z
~~~

该文件是实验后从 Bag 导出的数据，不是原厂驱动自动生成的独立文件。只提取 /cmd_vel 和 /vel_raw，时间范围限定为 summary.json 的 started_unix 至 finished_unix；elapsed_s 为各消息 Bag 接收时间减 started_unix。平移单位 m/s，角速度 rad/s。

两类消息频率不同，行不一一对应；画图应按各自时间绘制，不能把相邻两行强行配对。/vel_raw 是底盘自身反馈，不是独立外部测速真值。

### 10.3 监控、原始字节与时间对齐

monitor.jsonl 每行是一个 JSON，含 received_unix、safety、task、robot。received_unix 是 HTTP 采样接收时刻；状态里的 ROS stamp 和 odom_age_seconds 另有各自含义，不能当作同一时刻。

raw/*.bin 是 MGX23 接收的原始 NAVI 字节流，不是 CSV。原始设备时间与 ROS Unix 秒不是同一时间格式，不能直接相减；原始 bin 需按当前 MGX23 解析器离线解码，正式运行时段优先依据 Bag 的 ROS 时间和 summary 中的起止时间筛选。

所有轨迹与目标按同一原点/EPSG 直接叠加 x/y；不要分别减掉各自第一个点，那样会把本轮约 1.66 m 的起点接近段和真实偏差抹掉。
