# 覆盖任务起点与恢复航向对齐

按用户要求，为覆盖任务增加原地航向对齐，处理起点衔接和暂停后恢复时车头方向不一致的问题。本次保留用户任务原有的速度、前视距离、覆盖路径及安全策略，不包含前视调参、速度自适应或 GNSS 质量规则调整。

## 使用流程

- 明确开始覆盖任务后，距离首点超过 `start_tolerance` 时先接近首点，到达后进入 `ALIGNING`，沿覆盖路径首段方向对齐，再进入 `TRACKING`。
- 距首点较近时，直接进入 `ALIGNING`，对齐后再跟踪。
- 暂停后点击“继续任务”，先进入 `ALIGNING`：正式跟踪按当前位置对应路径段的切线方向对齐，保留原进度；接近起点途中恢复，先朝首点方向对齐，再继续接近。
- 对齐期间可以暂停和取消。暂停保持零指令，继续后重新计算对齐方向与稳定时间；急停、定位失效或控制权丢失沿用现有故障处理，不会自动继续。

各阶段保持 coverage 模式和同一次 tracking 控制权，不自动切换模式或重新从路径首点开始计进度。覆盖任务结束后重新开始一轮，仍需按原流程重新规划和明确开始。

Web“全覆盖规划与跟踪”的任务操作区显示“航向对齐中（原地转向）”、对齐目标类别和当前角度误差。进入对齐阶段本身仍属于运行中的任务，因此暂停/取消继续可用；对齐不是独立的自动任务启动入口。

## 默认规则与参数

| ROS 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `alignment_tolerance` | 0.08726646259971647 rad，即 5° | 允许的绝对航向误差，须大于 0 且小于 90° |
| `alignment_hold_time` | 0.5 s | 航向持续在允许范围内的稳定时间 |
| `alignment_max_angular` | 0.3 rad/s | 对齐角速度上限，实际还取任务 `max_angular` 的较小值 |
| `alignment_timeout` | 30 s | 每次运行中的对齐超时，超时结束为 FAULT 并发送零指令 |

参数在 `config/jetson_system.yaml`、统一 `agri_bringup/config/system.yaml` 和节点缺省值中保持一致。它们是跟踪节点级配置，不新增任务编辑页调参项；既有任务无需修改结构即可使用该功能。更改时核对实际启动 profile，不能在任务运行时修改。

对齐中前向及横向速度指令为零；航向误差超过阈值时，角速度按误差比例给出并限幅。进入允许范围后角速度也给零，连续保持规定时间，之后仍留一个零指令周期再进入后续行驶。期间若误差重新超出范围，则重新计算稳定时间。同一条重复 `/odom` 消息不能推进稳定保持完成；定位有效性与时间新鲜度检查仍由原任务协议约束。

该功能允许旋转，会扫过车体周围空间。原有雷达策略照常生效，当前仅前方 180° 保护的范围约定保留；它不代表增加了车体周向保护。软件验证不等于已完成真实安装方向、底盘惯性或实车精度验证。

## 记录与报告

每轮 `tracks/` 新增 `alignment_*.csv/.json`，记录时间、位置、实际航向、目标航向、对齐误差和原路径进度。接近仍写入 `approach_*`，正式跟踪仍写入 `track_*`。实时轨迹画布保留实际位置点，因此总轨迹点数可能包含多个阶段，不应等同于正式跟踪 CSV 的行数。

自动报告识别 `phases.alignment`，分别统计对齐航向和正式跟踪误差；轨迹图用紫色散点表示对齐位置，避免将不同恢复位置连接成虚假的行驶轨迹。没有显式对齐文件的历史任务仍按原统计口径处理，本次不重写历史报告。
