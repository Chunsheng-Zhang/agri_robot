# 简单靠边排线实现与验证

日期：2026-11-14。按用户确认的简单规则修改“一键优化规划”，不增加Web参数，不固定作业方向，不均分全部行间距；手工“生成覆盖路径”的原生曲线、回形保持原流程。

## 实现规则

每个既有候选角度均执行同样的排线过程：

1. 原始地块和安全区一起旋转到该方向的扫描坐标。安全区仍由完整原地转向圆包络内缩得到，尺寸、余量、原点不改。
2. 首行目标为原边界向内半个有效机具幅宽；若该位置不满足原安全区域，退到安全区域内部。以0.8m幅宽、0.296321m安全内缩的矩形为例，首行约距原边界0.4m。
3. 中间扫描线仍相隔一个机具幅宽。末侧若还有作业行足迹未覆盖的余量，在满足安全区域的目标位置补一条末侧线。只有最后一档间距可能小于幅宽，不重新均分所有间距。
4. 由Fields2Cover原生`Swaths.append(line,cell,width)`裁剪到原安全分区，保留所有有效行段；行端仍受原安全内缩约束，孔洞仍不可穿越。
5. 窄分区若恰好位于全局扫描线之间，用原生裁剪保留一条分区中线，不静默遗漏分区。扫描线恰与分区缝/角点重合时，仅作亚毫米数值避让，避免原生TSP重复端点；不移动边界、原点或降低安全余量。
6. 继续复用原生TSP和完整Route连接、停车转向标记、完整圆包络最终检查。有限角度粗搜/细化、入口起端比较和0.5/0.3/0.2评分不变。

这是每方向一套明确布局，不新增排线候选库或人工偏移参数。机具有效幅宽和评价幅宽不变。若完整旋转半径大于半幅宽，首末行仍须服从安全区域，不能承诺所有边缘都能覆盖；凹角、斜边和静态障碍仍可能留下漏带。全局扫描线按当前方向的原边界投影确定，并非独立沿每条斜边走一遍。

新智能路径`policy_version=5`，优化报告策略仍为`POINT_TURN_NATIVE_TSP`、`schema_version=2`。候选和最佳路径增加`row_layout.policy=EDGE_ALIGNED_FIXED_SPACING`，记录名义间距、机具幅宽、目标边距、扫描层数、末侧是否补行/最后间距、窄分区保留行数及净空不变标志。原始路径、历史报告及已保存任务不回写，加载旧路径不会自动变成新规则。

网页结果只增加一段规则说明，没有增加输入控件；旧报告无`row_layout`时沿用原显示。本轮作业质量报告也记录实际采用的排线规则。

## 代码与使用

- `agri_robot_ws/src/agri_path_planning/agri_path_planning/cell_routing.py::edge_rows`：靠边扫描线与原生安全裁剪。
- 同包`optimizer.py`：每方向传原始地块、v5元数据；原角度搜索和评分不变。
- 同包`native_route.py`：携带本轮排线审计信息。
- `agri_web/src/components/tasks/OptimizationResults.vue`：只读规则说明。
- `agri_backend/coverage_quality.py`：本轮报告说明。

使用“一键优化规划”重新生成即可采用新规则；沿用旧保存路径仍执行旧几何。保存新规划与开始任务继续分开，规划本身不取得控制权或行驶。运行服务是否配套加载须实读本轮路径`planning.policy_version`及`row_layout`，不能仅凭网页说明或磁盘源码判断。
