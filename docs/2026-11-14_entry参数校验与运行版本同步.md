# entry 参数校验失败与运行版本同步

2026-11-14，Web 全覆盖页面提示 `参数校验失败：entry: Extra inputs are not permitted`。

## 原因与证据

`entry` 是覆盖任务的人工入口字段。新前端在未设置入口时也会提交 `entry: null`，后端应接受这个字段。

磁盘 `agri_backend/missions.py::Mission` 已声明 `entry: FieldEntry | None = None`，但本机正在运行的 Uvicorn 是修改前的旧进程。实际查询 `http://127.0.0.1:8000/openapi.json`，其 `Mission.properties` 中没有 `entry`，旧严格模型因此将其作为额外字段拒绝。这与经纬度精度、地块凹凸或 Fields2Cover 计算无关。

同一时刻，只读查询运行中的 `/coverage_adapter/list_parameters`，也没有 `entry_config`。因此仅重载后端仍不足以让入口规划完整工作，需配套重载新版核心。没有通过放宽 `extra='forbid'`、忽略入口或删去前端字段绕过问题。

## 本轮处理

先核实原服务状态：Domain 225、`ROS_LOCALHOST_ONLY=1`、`chassis:=none`，MGX23/手柄/雷达/相机/视频均关闭，软件急停锁定、无控制权，多点及跟踪待命，只有之前的规划就绪记录；没有正在执行或暂停的任务。

通过入口既有回归（12 项 Python、4 项前端），构建 `agri_base`、`agri_safety`、`agri_path_tracking`、`agri_path_planning`、`agri_bringup` 五个包后，按捕获的原环境和完整命令重载后端及核心。仍采用 `config/jetson_system.yaml`，保留所有设备开关、coverage 模式和 ROS Domain；前端进程未重启。运行输出保存到项目目录，不配置系统自启。

重载后检查：

- 后端实际 OpenAPI 模型包含 `entry`。
- `/coverage_adapter` 已声明 `entry_config`。
- 直接访问 8000 以及通过网页 5173 同源代理，分别提交无入口 `entry: null`、带经纬度入口的 `POST /api/missions/preview`，均接受并返回 map 预览。
- 软件急停保持锁定、无控制权；各导航控制器保持待命。全部硬件仍关闭。

所有提交均为预览请求，没有保存测试任务、生成新规划、取得控制权或开始导航。已有任务和历史实验不回写。核心重载后旧实时参考不应视为已经加载，实际使用时重新生成或明确加载保存路径。

## 页面怎么恢复

在当前页面点击 **检查地块边界**，再按需要 **保存任务**、重新规划即可；这可以保留还未保存的输入。浏览器继续显示旧状态时，再在保留草稿后刷新。

以后遇到同样问题，先查询实际模型，而不是只看磁盘代码：

```bash
cd /home/zhang/agri_robot
agri_backend/.venv/bin/python -B - <<'PY'
import json
from urllib.request import build_opener, ProxyHandler
http = build_opener(ProxyHandler({}))
data = json.loads(http.open('http://127.0.0.1:8000/openapi.json', timeout=3).read())
print(list(data['components']['schemas']['Mission']['properties']))
PY
```

这里显式绕过 HTTP 代理，仅查询本机；如果网页通过 Vite 指向另一台机器，应核对实际 `AGRI_BACKEND_URL` 的后端，不能用本机源码推断远端版本。无入口时出现该错误同样可能是旧模型，因为 `null` 仍是一个提交的字段。

更新磁盘 Python 文件不会自动替换未启用 reload 的现有进程。实车环境必须先确认停车、任务结束和控制权释放，再按原配置重载；不要为消除字段报错在行驶中重启。
