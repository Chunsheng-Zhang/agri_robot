# Web 任务操作与旧 GUI 功能迁移

2026-11-13更新：“智能规划策略”改为固定原地转向、人工有效作业幅宽、自动安全地头、自动作业角度及往复式行顺序优化；固定权重为覆盖0.5/重复0.3/总长度0.2。原手工规划继续保留，操作与计算口径见 [原地转向智能规划](原地转向智能规划.md)。

更新日期：2026-10-30。适用于单机器人核心；原始 Yahboom 驱动保持不变。旧界面 `open_navigation_ws/gps_navigation/scripts/gps_field_gui.py` 及其 `panels.py`、`field_core.py` 用作功能参考，新 Web 不启动旧 GUI 的监听器、控制器或串口进程。

2026-10-30 布局调整：“任务管理”更名为“多点导航”，两类任务分别集中配置和执行。网址和已有任务数据不变。

| 栏目 | 操作内容 |
| --- | --- |
| 多点导航（`/tasks`） | 多点任务列表、新建/编辑/删除、JSON/CSV 导入、JSON 导出、航点与停留、RTK 采点、导航参数、检查与保存、开始/暂停/继续/取消、该类任务记录与数据下载 |
| 全覆盖规划与跟踪（`/planning`） | 覆盖任务列表、新建/编辑/删除、JSON/GeoJSON 导入、JSON 导出、地块与禁入区域、RTK 采点、规划与跟踪参数、保存/生成路径/取消规划、前往起点并覆盖、暂停/继续/取消、该类规划和执行记录与数据下载 |
| 系统总览 / 作业监控 | 总览保留任务状态摘要及栏目入口；监控集中地图、设备、安全状态和人工遥控，任务执行操作进入对应栏目 |

打开栏目只切换页面，不改变车辆模式或运行中的任务。多点栏目提供“基础待命 / 多点导航”模式按钮，覆盖栏目提供“基础待命 / 全覆盖作业”；监控页提供人工遥控所需的“基础待命”。切换车辆模式仍需明确点击，有控制权或任务在执行时需确认停止并切换。各栏目的任务控制栏固定绑定对应控制器，另一类任务的名称、进度和执行按钮不会混入。

机器人状态的“行驶速度（MGX23 水平速度）”直接订阅 `/mgx23/velocity_stamped`，依据 MGX23 手册 §2.2（第 6 页）的 NAVI 协议，以 `hypot(北向速度, 东向速度)` 计算，单位 m/s。向下速度不计入水平速度，前进、后退和横移均显示非负速率；不使用底盘反馈 `/vel_raw` 或 `/cmd_vel` 指令填充。后端在速度数据超过 0.5 秒、时间戳无效或数值无效时返回空值，页面显示“未更新”；页面同时检查接口新鲜度，轮询之间最多保留约 1.5 秒的读数。位姿和速度分别判断新鲜度。静止时设备会有小幅测量波动，页面保留两位小数，因此低于约 0.005 m/s 时显示 0.00 属于正常舍入。

定位节点按同一 NAVI 帧时间戳配对位置、姿态和速度，短暂等待迟到的速度消息，避免订阅回调顺序将有效速度变成默认零值。若速度缺失约 20–70 ms，仍允许发布位姿并保留未知速度的大协方差，保持定位可用；Web 速度不读取该默认零值。

| 经纬度多航点与停留 | 多点导航：航点顺序、每点停留、最大/最小速度、到点阈值、原地转向阈值和控制增益 |
| 作业幅宽、垄向与规划顺序 | 全覆盖规划与跟踪：幅宽、固定方向/自动搜索、牛耕/蛇形/螺旋顺序 |

未迁移旧 GUI 的动态原点/放置偏移、虚拟 GPS、另写一套覆盖预览算法、直接串口兜底控制和通杀进程重置。当前统一固定 UTM 基准，规划调用现有 OpenNav/Fields2Cover，控制经唯一 safety 入口；原始手柄正常映射和辅助按键继续复用原厂逻辑。最新增加原生四曲线及默认关闭的“允许倒车”，见[原生曲线与倒车跟踪](Fields2Cover原生曲线与倒车跟踪.md)。多机器人协同仍为预留页。

## 2. 启动与模式切换

“作业监控”和“设备与安全”页面的“实时设备与安全状态”提供“启用雷达障碍停车”复选框，默认不勾选。勾选后按雷达运动方向净空和扫描有效性保护；取消勾选关闭雷达停车。切换会先停车并释放控制权，任务需重新开始；不会解除独立急停。驱动通过 `start_lidar` 单独启动，已启用保护但没有有效扫描时不能行驶。页面刷新沿用安全节点的当前选择。

先按 [Web 实时数据显示与启动](Web实时数据显示与启动.md) 启动三个终端。本次增加了 `agri_interfaces` 服务包，必须先重新构建 overlay，再重启旧核心和后端；不要在旧进程旁再启动一套。

```bash
cd /home/zhang/agri_robot
bash scripts/build_core.bash
bash scripts/start_core.bash mode:=base chassis:=none \
  start_joy:=true start_lidar:=true start_camera:=true start_video:=true
```

示例不连接底盘。实车按现场验证选择 `chassis:=yahboom_x3`，端口、固定原点、安装参数和安全限速仍按统一 YAML 设置。硬件驱动在 Jetson 上运行，不由网页另开一份。只查看软件时不要照搬启动不存在的设备开关。

启动参数 `mode:=base/waypoint/coverage/following` 现在表示**初始选择模式**。定位、安全、多点/覆盖/示教跟随三类控制器及规划模块默认常驻，初始软件急停仍锁定；在对应任务栏目点击上方模式按钮切换，不需要重启设备。

切换会先撤销原控制权并输出停车指令，旧自主任务取消，进行中的规划取消并清除旧参考。新模式保持待命，不能自动恢复旧任务。同一模式按钮不会重复开始任务；人工停止仍使用任务取消、遥控释放或急停按钮。

ROS 模式服务为 `/system/mode/base`、`/system/mode/waypoint`、`/system/mode/coverage`、`/system/mode/following`（`std_srvs/Trigger`）。当前模式及版本从 `/safety/status` 反馈。自主控制权改用 `/safety/acquire_control`（`agri_interfaces/srv/AcquireControl`），带模式版本和任务代号；旧请求和旧释放指令不能作用于新控制权。原 SetBool 接口保留用于原厂手柄与既有明确人工操作。

若核心使用了自定义 `params_file`，启动后端前设置 `AGRI_SYSTEM_CONFIG` 为同一配置文件的绝对路径。Web 使用 ROS 发布的实际固定原点校验任务，配置文件用于初始默认参数和离线编辑；不提供原点修改入口。

## 3. 多点导航的完整操作

1. 打开“多点导航”，新建多点导航任务并填写名称。该栏目只显示多点任务。
2. 输入 WGS84 经度、纬度，按实际行驶顺序排列。可采集当前 RTK 点、调整点序、逐点设置停留；删除空白占位行。
3. 设置速度、到点距离、转向角阈值及增益。角度输入为度，后端转换后的 ROS 参数为弧度。速度和角速度开始时还会校验 ROS 安全上限。
4. 检查地图中点位，保存任务。保存成功不代表开始导航。
5. 选择“多点导航”模式，核对定位/安全状态、现场条件和目标位置，明确解除软件急停，再点击“开始多点导航”。
6. 观察状态从申请控制权到运行中，使用固定在内容顶部的任务栏暂停、继续或取消。恢复定位、解除急停或清障不会自动继续。

CSV 航点导入表头为 `longitude,latitude`，可选 `dwell_time`；任务 JSON 可完整保留参数。采集按钮依据数据新鲜度，不证明 RTK 已为固定解；定位质量仍需外场核验。

## 4. 全覆盖规划与跟踪

1. 打开“全覆盖规划与跟踪”，新建或选择覆盖任务，编辑外边界；至少 3 个不同点，按边界顺序排列。禁入区域须在外边界内且几何有效。
2. 可导入 WGS84 GeoJSON Polygon/Feature 或 `points/rings` 经纬度 JSON。旧 GUI 已带 `place_at` 偏移的米制地块不能当作经纬度导入。
3. 设置作业幅宽、方向、顺序、地头、半径、采样和跟踪参数，保存任务。
4. 选择“全覆盖作业”，点击“生成覆盖路径”。此步骤只规划，不驱动车体。越界、净空不足、或未明确允许的倒车路径不会作为可执行路径接受。
5. 等待路径就绪，在图中检查条带、地头和禁入区域。更改任务参数、任务版本、模式或外部参考路径后，需要重新规划/确认，不能直接沿用旧任务的结果。
6. 确认从当前位置到覆盖起点的直达通道可通行，定位与安全有效并明确解除急停后，点击“前往起点并开始覆盖”。距起点超过 `start_tolerance` 时，先复用单点导航控制器接近起点，再自动跟踪原覆盖路径；已在阈值内则直接跟踪。页面显示“前往覆盖起点（单点导航）”及剩余距离，衔接后显示“覆盖路径跟踪”。到达覆盖终点阈值后停车，可随时暂停/继续/取消。

接近和覆盖属于同一次执行，始终保持 coverage 模式和 tracking 控制权，不需要临时创建独立多点任务，也不会因自动切换模式使规划失效。接近速度及角速度沿用覆盖任务的 `speed/max_angular`。接近到点阈值为 `min(0.15 m, start_tolerance/2)`，随后发一个控制周期的零速度，再开始覆盖跟踪。`start_tolerance` 现在决定是否需要自动接近，不是超过后拒绝整个任务的距离上限。

“从当前位置”限定在同一固定原点、定位有效及配置的局部运行半径内。接近采用朝向单个目标点的直达导航，没有跨地块通行路线搜索或绕障，不能保证穿越禁入区域、沟渠或障碍物的路线可行。启动前需确认接近通道；既有急停、传感器有效性和按当前配置启用的雷达保护继续生效。暂停和清障后仍须明确继续；取消、急停、定位故障、人工接管或模式切换后不会自动恢复接近或转入覆盖。

页面作业方向为map网格东向0°、逆时针正，区别于MGX23原始北零顺时针航向。最小转弯半径约束行进连接曲线；双履带原地转向独立处理，不将Dubins半径设为零。倒车须显式勾选并保存、重新规划；当前仍不提供绕障。

所带 OpenNav 版本只在 configure 阶段读取最小转弯半径，宽度等部分参数可动态更新。因此改变半径时，后端通过原有 lifecycle manager RESET→参数更新→STARTUP 重新配置**规划器**，不重启底盘/定位。未确认成功不会开始规划或行驶。规划与控制命令服务各自校验模式和控制权限，页面成功提示不代替持续状态反馈。

## 5. 人工控制和安全

“作业监控”提供 Web 遥控。先切基础待命、释放原控制权并解除安全锁定，再启用遥控；随后按住方向按钮，或按住空格配合 W/A/S/D。松开方向即发零速，点击“停车并释放”结束会话。手柄继续使用原始映射，其人工接管优先于自主任务。

遥控请求带会话、序号和短期限；前端单条请求超时约 180 ms，指令期限不超过 0.2 s，过期后在下个输出周期清零；后端超过 0.5 s 没有新请求则释放控制权。ROS 还有独立指令超时保护。离页、页面隐藏和失焦会清零并释放；网络响应超过 0.3 s 时拒绝启用 Web 遥控，使用现场手柄处理。这些是软件阈值，不能作为硬实时保证；真实制动距离和硬件 watchdog 需实测。

2026-10-30 修复：浏览器提示 `signal is aborted without reason` 对应遥控心跳在 180 ms 后被前端中止，现改为中文说明“遥控通信超过 180 毫秒，请检查网络或使用现场手柄”。启用控制权后先发送并确认一条零速度心跳，再开放方向按钮；确认失败则退出并请求释放该会话，不重试运动或自动启用。失焦、隐藏、离页或安全状态变更会使待返回的启用请求失效，延迟响应不会重新开放方向控制。180 ms、0.2 s、0.5 s 等期限保持不变；停止/释放请求仍可能受网络影响，独立超时保护继续生效。

离线回归：`node --test tests/web_manual_control.test.cjs`，使用真实 TypeScript 实现和模拟 HTTP/UI 接口，验证中止错误中文提示、零速度确认、失败释放、延迟响应失效及后续心跳异常退出；不连接浏览器、ROS 或实车。该测试不代表现场无线网络已满足遥控延迟要求。

障碍物消失后，安全面板只有在净空持续满足恢复条件时才允许人工解除障碍锁定；之后仍需明确“继续任务”。未知/过期状态不显示为安全，不允许开始/继续。软件急停始终在顶部可见，不能代替硬件急停回路。

## 6. 数据在哪里，怎样对齐

任务配置保存在 `data/web/missions/<任务ID>.json`。每次覆盖规划或多点执行创建独立的 `data/experiments/<时间>_web_<随机后缀>/`：

```text
config/mission.json       本轮任务与版本、原点和参数
config/system.json        后端指定的统一 YAML 配置快照
config/field.json         本轮地块（覆盖任务）
config/waypoints.yaml     本轮目标点（多点任务）
paths/coverage_*.json     真实覆盖参考路径、投影、原点
tracks/track_*.csv        覆盖跟踪位置与误差
tracks/track_*.json       同名元数据和本次参考路径快照
tracks/approach_*.csv     自动接近覆盖起点的位置、目标距离与航向误差
tracks/approach_*.json    接近阶段的单点目标、出发位置与坐标元数据
tracks/waypoint_*.csv     多点位置、目标索引、距离/航向误差
tracks/waypoint_*.json    同名元数据和本次目标点快照
raw/mgx23.bin            新任务的 MGX23 原始接收字节
raw/chunks.csv           原始片段序号、时间及字节位置
telemetry/               指令、MGX23、底盘反馈和采集完整性清单
analysis/                任务结束后生成的四图、指标 JSON/CSV 和说明
run.json                 阶段、模式版本、状态与失败原因
```

多点 CSV 列为 `stamp,x,y,yaw,target_index,distance,heading_error`，目标索引从 0 开始。自动接近的 `approach_*.csv` 使用相同列，目标索引固定为 0，JSON 的 `task_type` 为 `coverage_approach`。跟踪 CSV 列继续为 `stamp,x,y,yaw,cross_track,heading_error,progress`，只记录覆盖跟踪阶段；同名 JSON 的 `approach_csv` 关联接近记录。取消在接近阶段时，跟踪 CSV 可能仅有表头。实时 `/tracked_path` 包含接近和覆盖两阶段，`/tracking/status.phase` 区分 `APPROACHING/TRACKING`，接近期间覆盖弧长进度为零。各文件位置均为 map 下的 `base_link`、单位 m，角度 rad，时间为 `/odom` ROS 主机接收时间。元数据包含同一固定原点和 EPSG；离线直接叠加 x/y，不分别按各自起点归零。界面路径任务进度按路径弧长估计、到点完成后记 100%，不等于实际作业面积覆盖率。

轨迹 CSV 按控制采样记录；携带完整历史的 ROS 轨迹图降低为最多约 2 Hz，并在结束时补发完整尾部，避免 Jetson 重复传输上万个点影响状态与视频。图中保留最近一次实际轨迹作对照，新一轮开始后清空重记；精确离线比较使用该轮 CSV 和同名参考快照，不凭显示查询时间判断轨迹属于哪一轮。

两个任务栏目各自显示最近 50 轮 Web 运行中属于本类的记录并提供下载；“系统设置”的“系统信息与运行记录”保留全部类别汇总。2026-11-04 起，新任务开始前自动记录 MGX23 原始字节、解析数据、速度指令和底盘反馈；完成、取消或故障后后台生成四图（轨迹、速度、横向误差、航向误差）与指标。未结束或采集/分析尚在收尾时禁止下载；ZIP 包含已生成配置、规划、轨迹、新增 BIN、图表和指标，不包含 rosbag 或视频。历史任务不回填。详见 [任务数据采集与指标分析](任务数据采集与指标分析.md)。完整 ROS 录包仍按 [室外实验指导文件](室外实验指导文件.md) 执行。Web 操作事件在 `data/web/events.jsonl`，ROS 安全事件继续按 `event_directory` 保存。

每个记录表的“归档”右侧都有“删除”。点击后核对名称、版本和时间，再确认“删除记录”；只移除该运行记录条目，`data/experiments/<运行ID>/` 的原始数据和 `data/web/missions/` 的任务配置保留，不释放原始数据占用的磁盘空间。删除结果在三个记录表中同步生效，标记保存在 `data/web/deleted_runs/<运行ID>.json`，重启后不会重新列出。未结束、暂停或控制器仍在使用的记录不允许删除，后端再次核对状态。删除当前就绪的覆盖规划记录会清除其待开始关联，须重新生成路径；不会向车辆发送取消、模式切换或运动指令。删除事件以 `RUN_RECORD_DELETED` 留存，不自动清理任何历史记录。

后端重启只重新关联已有目录与实时状态，不自动恢复运动。全局原点、任务版本或参考路径不匹配时拒绝开始。设置页面继续只读展示配置来源，不修改原点、杆臂、车体尺寸或安全阈值。
