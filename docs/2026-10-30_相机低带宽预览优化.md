# 相机低带宽预览优化

日期：2026-10-30（Asia/Shanghai）。用户说明项目对相机要求不高，希望减少图像流量造成的网页卡顿和超时。本轮只修改项目网页及测试、文档，不改动系统、厂商工作区、相机驱动或车辆控制期限。

## 网页行为

相机卡片显示“相机辅助画面”，进入页面默认暂停，只有点击“开启画面”才传输图像。预览设置为 320×240、JPEG 质量 40，每张图片收到后再等 0.5 s 请求下一张，因此最多 2 帧/秒，网络较慢时实际帧率会降低。

每个面板最多一个在途截图请求，不累计待显示帧。截图响应超时 1.5 s 时中止，失败后等待 2 s 再试；这些重试只获取画面，不取得运动控制权。配置地址查询仍使用原 API 查询期限。

点击暂停、标签页隐藏、相机状态失效或路由卸载时中止在途截图、撤销图像 Object URL 并清空画面。恢复可见仅恢复用户本次已开启的预览；新进入相机面板仍默认暂停。暂停和后台不再持续传输图片。

“下载图片”在此仅指通过网络传到浏览器显示。图片通过内存 Blob/Object URL 显示，旧 URL 及时释放，页面没有自动另存相机图片的操作。

## 实现和设置来源

- `agri_web/src/composables/useCameraPreview.ts`：预览状态、单请求调度、超时取消和内存释放；`cameraPreview` 常量为宽高、质量及帧间隔的规范来源。
- `agri_web/src/components/dashboard/CameraMonitor.vue`：开启/暂停按钮和低带宽预览显示。
- 仍调用已有 `/api/camera/stream-info` 读取视频地址，再将同一服务的 `/stream` 转成 `/snapshot`，覆盖宽高和质量参数。请求 ROS 话题分隔符 `/` 保持原样。
- 厂商现有 C++ `web_video_server` 已支持 `/snapshot`，返回 `image/jpeg`，无需增加服务或更新依赖。FastAPI 不搬运、转码每张图片，仍通过现有网页代理直接访问视频服务。

降低的是网页预览大小和图片请求频率，原 ROS 图像采集参数仍为现有配置。没有把一个无效 `fps` 参数塞给旧视频服务器，也没有仅隐藏画面而继续后台接收连续 MJPEG。

相机预览回归 7 项、通信回归 7 项、遥控回归 7 项通过，共 21 项。覆盖默认不下载、正确截图参数、单请求串行、暂停/隐藏/断线/卸载取消、迟到图片不能覆盖新会话、旧图片内存释放、错误退避和截图超时。浏览器测试脚本已适配按需开启与 JPEG 截图并通过语法检查；当前环境未运行真实浏览器自动化。前端类型检查及构建成功，1668 个模块。

### 真实相机截图采样

通过 Jetson 本机的网页代理请求一张原规格截图与五张预览截图，均返回 HTTP 200、有效 JPEG，并确认解码尺寸。实际相机图像未保存到文件，仅保存统计 JSON：`.diagnostics/camera_preview/measurement.json`。

| 项目 | 本次取样结果 |
| --- | --- |
| 原 640×480、质量 50 单张 | 37,381 字节 |
| 新 320×240、质量 40 五张 | 每张 8,897–8,951 字节，平均约 8,923 字节 |
| 最多 2 帧/秒估算图片内容 | 约 17,847 字节/秒，即约 17.4 KiB/s，不含 HTTP/TCP 开销 |
| 新截图本机代理响应 | 约 27–80 ms |
| 同期状态查询 | 约 13–34 ms，ROS 桥接在线 |

每张预览图片约为原规格的 24%，还通过低帧率进一步减少连续传输次数。体积会随场景变化，以上不是固定带宽承诺；本机代理测试不能替代用户电脑经过无线链路的实际表现。

本轮修改由 Vite 加载，没有重启核心、后端或相机驱动，没有解除急停、取得车辆控制权或执行运动。浏览器刷新后可在相机卡片点击“开启画面”查看；无需更改一键启动命令。
