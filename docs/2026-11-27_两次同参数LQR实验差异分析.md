# 两次同参数LQR实验差异分析

对比用户已完成的两次实验：

- A：`data/experiments/20261127_083324_157825_web_1e6d040f`
- B：`data/experiments/20261127_091746_560120_web_d31cfad4`

用户确认两次之间电池、载荷、轮胎和地面条件无变化。本轮仅分析原始归档与离线模型，没有修改实车参数、控制器、原始实验或执行新运动。

## 直接结论

参数和路径相同，但B的转弯及出弯摆动更强，整体横向RMSE增加约50.47%。起步条件不同是事实，但剔除起始5秒后差距仍在，不能把全程变差都归因于起点。

数据与离线敏感性对照更符合“当前运动学LQR对执行响应、采样相位和扰动的容忍度不足，转弯后产生较强的超调和衰减摆动”的解释。这是有证据支持的控制机制判断，尚不能从两次记录唯一确定最初诱因。不能据此断言换了电池、地面更滑、MCU固件变化，或某一个真实机械参数确实变了。

## 相同的条件

- 两份`config/mission.json`中的全部任务参数一致，均为LQR、速度上限0.5m/s、角速度上限1rad/s、Dubins、最小半径1m、采样间距0.1m，其他任务控制参数也一致。任务版本从v5变为v10，不代表参数内容不同。
- 两份`config/tracking_controller.json`一致：实现标识`agri_path_tracking.algorithms.v1`，`Q=diag(8,3)`，`R=0.5`。
- 两份`config/system.json`内容完全一致。该文件是启动配置快照，其中默认PP/0.1m/s不能冒充实际任务算法与速度；实际值还核对了任务、轨迹元数据与原始状态。
- A、B的RUNNING状态分别有3034、3435条，算法均为`lqr`。
- 两份覆盖路径的688个点完全一致，点序列规范化JSON SHA256均为`fc104a6cb5ac9ede9dc8722bfa56e28551a2522cbd4086aaefb093f7a9759333`，参考指纹均为`59bbae11e468b41f4224c4a2f2db93039a8fed97216a8ee6b7fa4fcfec787468`。比较保持同一固定map原点，没有分别平移轨迹。
- 雷达保护均未启用，记录中没有暂停，控制权只有空闲或tracking，未观察到切换到ROS手动控制。

这些归档证据支持参数与路径一致，但没有完整不可变的运行二进制/所有实时参数指纹，不能声称已独立证明两次进程的所有内部状态完全相同。

## 起始条件确实不同，但解释不了全部差距

| 正式跟踪第一帧 | A | B |
| --- | ---: | ---: |
| 横向误差 cm | +9.88 | -14.09 |
| 航向误差 ° | +8.92 | -9.50 |

两次都是在现有10°对齐容差内开始，起始横向误差方向相反。B从上一轮终点附近接近起点，A的接近路线不同；B的额外总用时主要还包括更长的接近/对齐阶段。正式跟踪分别约136.8s与137.4s，相差较小。

第一条直线到参考进度5m附近时，两次横向偏差都已在约0.3cm内。剔除起始5s后B的横向RMSE仍明显更高。因此“只要把起点放好就能解决全程差异”缺乏支持，后续入弯和出弯动态更值得优先处理。

## 实际角速度响应及离线敏感性对照

当前LQR以横向/航向误差为状态，按0.5m/s和0.05s建立固定增益，并叠加当前局部曲率前馈。没有显式纳入实际角速度执行响应或未来曲率预瞄。

用实际驱动指令和MGX航向差分进行同一方法的拟合，两次均仅使用正式跟踪去掉起始5s后的有效样本：

| 角速度等效拟合参数 | A | B |
| --- | ---: | ---: |
| 增益 | 0.8511 | 0.8360 |
| 一阶时间常数 s | 0.7387 | 0.7910 |
| 网格等效延迟 s | 0.025 | 0.050 |
| 同数据拟合RMSE rad/s | 0.0361 | 0.0512 |

角速度限幅未充分激励辨识，拟合中的limit值不解释为真实机械上限。等效时间参数包含车辆响应、MGX滤波/差分、采样相位及主机时间对齐，不能说“MCU多延迟了25ms”或“电机肯定慢了0.052s”。两套参数也能交叉解释两次记录的大部分响应，缺少置信区间，因此不足以证明真实机械动态发生了确定变化。

为了检验机制，在隔离的纯平面仿真中，固定路径、控制器、初始条件、线速度模型和10Hz定位，只交换这两套等效角速度模型；另外单独交换两次实际起始位姿。没有ROS、设备或实车运行。

| 起始位姿 | 角速度模型 | 模拟横向RMSE cm |
| --- | --- | ---: |
| A | A | 2.841 |
| B | A | 3.031 |
| A | B | 3.897 |
| B | B | 3.869 |

在这个简化模型中，仅交换起始位姿影响较小，交换幅度不大的响应模型则能明显放大误差，说明当前LQR对动态/相位误差较敏感。这是敏感性演示，不是因果归因：模型参数来自同数据拟合，未回放全部真实噪声、抖动和轮地行为，模拟结果也没有完全复现两次实测的3.594/5.408cm。不能把模拟差值当作各物理原因的真实贡献。

## 哪些原因目前不受数据支持

- **明显提速**：MGX平均速度仅相差约0.004m/s，不足以直接解释为第二次任务速度设错。
- **LQR算不动**：计算耗时P95约0.488/0.469ms，最大约1.631/1.803ms，均很低。
- **MGX明显掉帧增加**：两次NAVI设备时间均按10Hz，无估算缺失槽，记录器无丢弃报告。
- **定位传输整体明显变差**：里程计来源到记录器年龄P95约49.6/38.1ms，最长接收间隔321/287ms，B没有整体劣化。不过这不是控制器实际使用定位年龄的直接测量。
- **已证实GNSS失效**：两次设备GnssReject/GnssLost均未置位，内部accuracy均值也接近约0.00285m。但内部估计和未置位不能证明绝对位置/航向噪声完全相同，更不能等价于独立真值。
- **电池、载荷、轮胎或地面改变**：用户确认没有变化，不以这些假设当作结论。

控制指令来源到记录器年龄P95从约73.8升至85.1ms，仍有调度/接收抖动。控制器20Hz、定位10Hz，每帧采样相位不会完全相同，可能成为弱阻尼闭环中的扰动，但这些记录不足以单独确定其贡献。

## 后续处理方向

1. 保留当前参数和路径作为基线，统一接入方向、起始位置和航向条件；做多次交替重复，评价均值、P95和较差轮次，不能以单次好结果代表稳定水平。
2. 在已有离线平台优先验证角速度响应增广、曲率预瞄与弯前减速，观察入弯峰值和出弯振荡是否同时改善。
3. 研究实际车速增益调度及阻尼/控制变化率代价，不仅提高横向纠偏力度或放宽角速度上限。
4. 需要实车验证时，再由用户明确安排；可先用全程0.3m/s与0.5m/s重复对照，随后引入局部弯道速度规划。本轮未执行这些试验。

当前最明确的工程问题是重复性与闭环鲁棒性，而非发现某项保存参数不同。最初微扰的唯一物理来源仍未确认。
