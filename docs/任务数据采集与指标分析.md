# 任务数据采集与指标分析

2026-11-15 更新。适用于更新后的 Web 多点导航、全覆盖与路径跟随任务。此功能为以后新开始的任务保存数据，不回填历史实验。通信记录和中文实验报告的完整口径见 [任务通信记录与实验汇总](任务通信记录与实验汇总.md)。新增三项作业精度按用户文件公式计算，见 [作业精度三项指标与国标公式](作业精度三项指标与国标公式.md)。

## 任务操作与生成时机

保持原有操作：保存任务，覆盖任务先规划，再明确点击开始。后端在请求控制器开始之前创建记录文件；记录器只订阅数据，不连接设备、不发布速度、不改变定位或安全策略。若记录文件无法创建，则该次开始请求被拒绝，车辆不会因该请求开始导航。

任务暂停期间保留采集，继续仍写同一次记录。控制器报告完成、取消或故障后，继续采集约 0.5 秒用于保留停车过程，随后关闭文件并在后台生成分析报告；不需要网页持续打开或轮询。控制器状态连续 10 秒不可用时，采集标记为 INTERRUPTED 并结束；这不是车辆已停止的确认。后端正常退出会关闭记录并标记中断，不自动恢复任务。断电、进程被强制杀死等情况下，记录可能不完整，`RECORDING` 标记不应视为已关闭或已分析。

写盘由后台线程完成，绘图由独立 Python 进程完成，均不在 ROS 回调中执行。队列有容量上限，丢弃计数、写盘错误及 MGX23 原始片段序号间断保存在记录清单中；报告不会把缺失信号解释为零速度。任务完成是控制器状态，数据记录完整性与图表生成状态须分别检查。

开始服务发生通信异常或超时时，不立即假定任务被拒绝或已停车，采集继续等待控制器状态。10 秒内一直没有观察到 ACQUIRING/RUNNING/PAUSED 时，采集以 START_UNCONFIRMED 结束，不能用它确认车辆停止。明确拒绝或已生成采集文件的失败尝试保留原文件；覆盖任务需重新规划生成新轮次后再开始，不能覆盖旧轮次的原始文件。

## 每轮目录

```text
data/experiments/<本轮_web_ID>/
├── run.json
├── config/                     # 原有任务、边界和系统配置快照
├── paths/                      # 原有覆盖参考路径
├── tracks/                     # approach、alignment、track 或 waypoint CSV/JSON
├── raw/
│   ├── mgx23.bin                # 本轮收到的原始设备字节
│   └── chunks.csv               # 原始片段的字节偏移、长度、会话、序号与时间
├── telemetry/
│   ├── motion.csv              # 控制器、安全输出、驱动输入及底盘反馈
│   ├── mgx23.csv                # 原始经纬度、姿态、NED速度、精度字段和尾部整数
│   ├── odometry.csv             # 统一定位输出的位置、航向与航向差分角速度
│   ├── status.jsonl             # 任务、安全状态和安全事件
│   └── recording.json           # 采集状态、各话题条数、丢弃/错误/片段间断
├── communication/              # 新任务自动创建；不对历史任务补录
│   ├── metadata.json           # 测量范围、QoS、诊断参考线与限制
│   ├── ros_timing.csv          # 消息接收时刻、源时间和消息年龄
│   ├── http_server.csv         # 实际后端查询耗时，不是浏览器RTT
│   ├── navi_frames.csv         # NAVI校验、设备时间与准确度
│   ├── summary.json            # 缺口、匹配与延时分布统计
│   └── summary.csv             # ROS/HTTP耗时汇总表
└── analysis/                   # 与 config/paths/tracks 同级
    ├── trajectory_and_speed.png # 四图总览，2×2 排列
    ├── trajectory.png           # 参考路径、实际轨迹、边界与接近轨迹
    ├── speed.png                # 安全速度指令、驱动指令、底盘反馈、MGX23速度
    ├── cross_track_error.png    # 覆盖阶段横向误差；多点任务对应 target_distance.png
    ├── heading_error.png        # 覆盖或多点任务的航向误差，单位度
    ├── metrics.json             # 完整指标与数据来源、限制说明
    ├── metrics.csv              # 按阶段汇总的误差指标，便于表格软件分析
    ├── report.md                # 中文本轮实验汇总，以跟踪精度评价为主
    ├── standard_accuracy_report.md # 直线、交接行、曲线作业精度及文件公式说明
    ├── standard_accuracy.json    # 三项完整结果；无适用段/数据不足保存未知及原因
    ├── standard_accuracy.csv     # 分段和汇总，N=50、分母N−1，单位cm
    ├── standard_accuracy_samples.csv # 每段50点与交接行配对坐标，供复算
    ├── tracking_samples.csv     # 有正式覆盖样本时，逐点标明起步/直线/转弯
    ├── communication.json       # 通信汇总，也写入metrics.json
    ├── communication_loss.png   # 消息缺失率与记录器丢弃；非IP丢包率
    ├── communication_latency.png # 消息年龄、后端耗时及整轮分位数
    ├── communication_plot_data.json # 图表窗口分子/分母、时基和阶段明细
    ├── README.md                # 图表和统计口径说明
    ├── analysis.log             # 离线分析进程的输出及异常信息
    └── status.json              # PROCESSING / SUCCEEDED / FAILED
```

规划成功但尚未开始时，不采集运动数据、不生成已执行任务的误差图。Web 运行记录“归档”下载会包含新增的 BIN、PNG、说明和数据文件。采集或分析尚未结束时会提示稍后再下载；单次归档仍受 200 MB 大小限制，超过时从实验目录复制。图表缺少某一路数据时会标明，检查 `recording.json` 的话题条数和错误后再决定是否用于研究。

## 数据来源与时间

| 文件/话题 | 保存内容与约定 |
| --- | --- |
| `/mgx23/raw`，String | 驱动新增的原始数据旁路：JSON 封装接收时钟、设备驱动会话、片段序号和 Base64 字节。后端解码写 BIN，不将 Base64 文本当原始二进制。它是协议解析和数据有效性过滤前的接收字节，包含可能被丢弃的无效帧。原有驱动连续 BIN 日志照常保存。 |
| `raw/chunks.csv` | 用 offset/size 对应 BIN 中的每个片段。TCP 片段不等于完整协议帧；UDP 片段保留数据报界限。第一片段可能从帧中间开始；驱动重启、序号缺口和接收端队列丢弃需结合清单分析，不能宣称抓到了设备全部连续输出。 |
| `/mgx23/position` | 纬度、经度、高度、NavSatFix 状态。当前状态不能用于宣称 RTK FIX 已验证。 |
| `/mgx23/attitude_stamped` | v1/v2/v3 = roll/pitch/设备北零顺时针 yaw，单位 rad。 |
| `/mgx23/velocity_stamped` | v1/v2/v3 = 北/东/下速度，单位 m/s；速度图显示 `hypot(北,东)` 的无符号水平速度。 |
| `/mgx23/accuracy`、`/mgx23/status` | 保存驱动发布的数值；status 是未解释的尾部整数，不推断其 RTK 有效位。 |
| `/control/waypoint/cmd_vel`、`/control/tracking/cmd_vel` | 控制器的 TwistStamped 指令，保留源时间戳。 |
| `/cmd_vel`、`/base/driver_cmd_vel` | 安全模块最终输出与底盘适配后的 Twist 指令。 |
| `/vel_raw` | 原厂底盘 Twist 速度反馈，仅用于实验记录，不接入定位，也不替换 Web 的 MGX23 实测速度。 |

`motion.csv` 各行有 topic、源时间（有 Header 才填）、ROS 接收时间、Unix 接收时间、单调接收时间、坐标系、linear_x/linear_y/angular_z。无 Header 的 Twist 没有独立测量时刻，不能伪造同步或用时间完全相同的假设比较。MGX23 CSV 使用相同的三类接收时间，另保存源时间和 v1/v2/v3/status；按 topic 区分字段。相机图像和雷达扫描不在本功能中录制，避免显著增加体积。

速度图横轴以正式跟踪首条轨迹时间为零；负时间属于接近或开始前采集。各路曲线使用各自的时间：带源时间的 MGX23 使用源时间，无 Header 的速度指令/反馈使用接收时间。MGX23 水平速度与带符号的车体前向速度含义不同，尤其倒车或横移时不能直接相减当作严格速度误差。`motion_by_topic` 统计整个采集窗口内的速度数值，包含接近、暂停和停车尾段，不是指令与反馈相减的误差统计。新汇总另外按源时间匹配正式跟踪附近的MGX23速度与控制器水平速度模长，提供平均差和RMSE；不补偿滤波/惯性滞后，不能当纯通信延迟或固件限速证明。图中的任务配置速度虚线仅为参考值。

## 指标口径

2026-11-15新增的直线作业精度、交接行精度、曲线作业精度使用GB/T 46270—2025公式（1）/（2），每组50个空间等距点、分母49；与下面原有按原始记录统计的指标分别保存。交接行先计算 `abs(h-H)` 再取样本标准差，按空间相邻行而非TSP访问顺序配对。原地转向和换行连接不作为曲线作业；没有适用段或足够样本时显示未测，不填0。结果仅代表已观测连续路段，不自动认定满足完整国标试验条件。详细公式、分段规则和文件见 [三项指标说明](作业精度三项指标与国标公式.md)。

覆盖阶段使用 `track_*.csv` 的 cross_track、heading_error 和 progress，计算横向误差的带符号均值、MAE、RMSE、绝对值 P95、最大绝对值，以及航向误差的相同指标（rad 和 deg）。P95 使用排序后线性插值；按原始记录点统计，没有按距离重采样或按时间加权。2026-11-05 增加显式航向对齐后，对齐写入单独的 `alignment_*.csv/.json`，报告列为 `phases.alignment`，不混入正式跟踪误差；旧轨迹原有的初始对齐样本保留，不回写历史数据。暂停和低速转弯的权重仍与记录策略有关，应结合曲线分析。

接近轨迹在总览图中单独标识，指标单独放在 `phases.approach`，不混入覆盖误差。两阶段还记录采样数、起止 ROS 时间、轨迹折线长度和采样间隔；覆盖阶段报告最后进度和终点距离。多点任务的 distance 是到当前目标点的距离，不称作横向误差。

航向对齐文件记录 `stamp,x,y,yaw,target_yaw,heading_error,progress`，单位分别沿用 ROS 秒、米和弧度。起点和各次恢复对齐写在同一对齐文件中；它们可能处于不同位置，不能把位置之间的连线或整个时间跨度当作原地转向的实际行驶距离/持续时间。轨迹图使用紫色散点标出对齐位置，航向指标单列统计。细分每次对齐过程时结合 `telemetry/status.jsonl` 中的 ALIGNING 阶段。

报告先核对固定原点、map 坐标系和跟踪元信息中的参考路径与规划路径一致性；不能通过平移、归零或旋转来美化对齐。误差来自同一套 MGX23 定位，不能代替独立真值精度或实际机具作业覆盖率。失败、中止任务保留本身的结果与已有样本，不标成成功完成。

## 更新部署

在接设备的 Jetson 上同步代码后，停车并核对当前任务、控制权和急停，再构建更新过的 MGX23 驱动、重启该驱动及后端。不要在行驶中重启服务。原始字节旁路需要更新后的驱动；旧驱动仍可定位，但记录会报告 `/mgx23/raw` 缺失。

```bash
cd /home/jetson/agri_robot
source scripts/setup_environment.bash
export TMPDIR="$PWD/.runtime/tmp"
export ROS_LOG_DIR="$PWD/.runtime/ros"
export MPLCONFIGDIR="$PWD/.diagnostics/matplotlib"
export PYTHONDONTWRITEBYTECODE=1
cd mgx23_ws
colcon build --packages-select mgx23_driver --event-handlers console_direct+
```

后端新增绘图依赖 `matplotlib>=3.5,<4`。当前开发电脑已有可用版本；Jetson 若缺少，只在项目后端虚拟环境内安装匹配版本，不升级系统 Python 或系统软件。完成运行后如需重新生成本轮报告，可在项目根目录执行：

```bash
MPLCONFIGDIR="$PWD/.diagnostics/matplotlib" \
agri_backend/.venv/bin/python -B -m agri_backend.experiment_analysis \
  data/experiments/<本轮_web_ID>
```

该命令不发布 ROS 消息，会拒绝正在采集或尚未结束的任务；只重写指定轮次的 analysis 生成物，原始文件保留。新任务会自动生成报告，不需要每次手工执行。
