## 重要异常与排除

用户另明确确认：三轮自动覆盖跟踪期间均未操作手柄或手动移动车辆，只在最后转向测试操作过。确认记录保存在总索引和三轮各自 `config/operator_annotation.json`；未直接记录MCU SBUS通道原始值，操作者确认与硬件输入记录应区分。

扩展响应首次左转从09:56:58开始。该段指令0.30rad/s，但MGX23航向差分和底盘反馈出现约2rad/s峰值。用户随后明确确认该时段“操作过手柄或手动转动车辆”，具体方式未细分。因此首次左转、初始静止及邻接归零段标为人工干预，排除于执行器辨识和自主控制器因果分析，图中红色背景标出；不能把该峰值归因为控制器自行失控。其他段仅作为待审核的响应候选，不把整轮当成无人为干预的完整标定试验。

同组四段原地转向与两段弧线均记录到下一阶段标记，非零段时长完整。但最后 `arc_zero_2` 归零约3.3s时，一次已确认的**零速度**控制请求耗时184.2ms，超过本轮实验脚本180ms上限。脚本停止、释放控制权，没有重试或恢复；本轮 `FAULT: Control API too slow` 和原始traceback保留，原计划剩余零速尾段未完成。180ms是本次独立实验脚本门槛，项目Web遥控原有500ms应答、约200ms指令期限未修改。

记录器文件关闭、队列无丢弃与实验成功是不同判断。总核对结果为 `CHECKED_WITH_EXCLUSIONS`，不把这组写成全部通过，也不把人工干预段用于拟合。

## 回去后的优化顺序

1. 从未干预短时响应、连续补充记录及正式覆盖段辨识前向与转向响应，区分原地和行进转向；审核人工干预标记与截断，不把全部记录无条件投入拟合。
2. 用一轮辨识、另一轮验证，检验速度/角速度预测、短时位姿预测和左右差异；既有架空试验仍单独保留，不混作地面模型。
3. 在 `tracking_simulation/` 内对比弯道降速、曲率预瞄、执行响应增广/补偿及速度相关LQR增益，保留原算法对照与参数快照；避免只靠理想模型筛选。
4. 分开核对接近终点约十余厘米残余误差和±10°对齐门槛，不能把首段误差当成弯道精度；再比较去首5s及共同进度统计。
5. 通过留出数据检验后再实车验证优化版本，本次结果不代表优化已经完成或已获得独立厘米级绝对精度。

最终查询快照在总索引 `config/final_robot.json` / `final_devices.json`：基础待命、无控制权、零线/角速度指令，MGX23水平速度约0.0034m/s。核心、后端、网页及原设备服务继续运行；本次观察进程已收尾，没有自动恢复任何任务，也未commit/push。
