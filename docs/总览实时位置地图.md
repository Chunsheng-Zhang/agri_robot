# 总览实时位置地图

适用日期：2026-10-30。系统总览的“机器人实时位置地图”用于查看车辆位置、朝向及周边地貌；多点导航、全覆盖规划与跟踪和作业监控保留原米制路径画布。

## 使用

1. 打开系统总览，点击地图右侧“配置底图”。
2. 输入自己的天地图服务 Key，点击“保存并加载”。Key 只存于当前浏览器的 localStorage，不发送到项目后端、不写入代码或日志；瓦片请求会将 Key 提交给天地图服务。需按服务要求配置网页来源权限，电脑需能访问互联网。
3. 默认使用“卫星影像”，可切换“普通地图”。Key 的服务权限或网络异常时，点击“重新加载底图”；没有 Key 时仍可显示车辆标记及坐标。

配置针对当前浏览器及页面来源；更换浏览器、协议、IP/域名或端口后需要重新填写。“清除配置”删除此浏览器内保存的 Key 并停止底图请求。不要把 Key 发到聊天、提交到 Git 或放入实验报告。

地图初始视野使用后端返回的固定原点，不将该原点绘制为车辆。收到有效车辆定位后显示蓝色标记，箭头为车头方向；航向缺失时只显示圆点。失联或过期后灰显“最后位置”及定位时间，不能据此认为车辆仍在原地。项目当前不强制 RTK FIX 等级，蓝色标记不代表独立验证了绝对精度。

“跟随车辆中”只在车辆离开视野中心区域（横纵各 20%–80%）时移动地图，避免画面频繁平移。拖动地图后自动暂停跟随；“回到车辆”定位到当前或最后位置，“跟随车辆”恢复跟随。展开地图占据主要内容区域，保留应用顶部的急停入口；再次点击或按 Escape 收起。宽屏左右并排时，地图卡片与右侧机器人状态卡片等高，画布自动填充增加的空间；屏幕宽度不超过 1000 px、上下排列时，地图画布保持 240–360 px。

实时的是车辆位置，卫星影像是已有底图。影像清晰度、更新日期和配准精度取决于数据源；原生瓦片最多按配置使用 18 级，继续放大属于显示放大，不会增加原始地面细节。底图不用于判断厘米级跟踪精度，也不提供绕障或安全通行保证。

## 数据与性能

- 新字段为现有 `/api/robot/status` 的 `map_position`，来源为 MGX23 定位所产生的 `/odom` 中 base_link 位姿，按 ROS 发布的固定原点和 UTM EPSG 转回 EPSG:4326。原始 GNSS 经纬度字段继续保留，不能用天线位置替换车体位置。
- 车头朝向先在 UTM 中沿 ROS 网格航向前进 1 m，再反算该方向的真北方位角，处理东零逆时针与北零顺时针及 UTM 网格收敛差异；只影响地图显示。
- 位置年龄超过 1 s 或 ROS 固定原点未知时，后端不提供新的地图位置；前端沿用现有包含网络传输时间的新鲜度判断。复用约 2 Hz 状态轮询，不新增位置请求，不在总览请求航点、参考路径和完整实际轨迹。
- Leaflet 仅安装在项目，固定版本 1.9.4；类型声明固定版本 1.9.21。既有依赖版本不升级，系统环境不升级。
- 位置更新只移动一个标记，航向或新鲜度没有变化时复用原有图标。初始原点视野只设置一次，任务信息刷新不再复位人工缩放/平移；首次车辆定位也保留已选择的缩放级别。瓦片在拖动期间按 200 ms 限频更新，缩放时及时更新，保留少量周边瓦片，不启用增加瓦片请求的 Retina 模式；浏览器按服务响应缓存图片。
- 页面隐藏、地图滚出视野或离页时移除瓦片层并取消未完成请求。底图失败或单批加载超过 8 s 时停止该批请求并提示人工重试，避免无限自动重试。底图与相机、状态接口、车辆控制分离。

## 验证

离线命令如下，均不启动车辆或取得控制权：

```bash
cd /home/jetson/agri_robot
TMPDIR="$PWD/.runtime/tmp" PYTHONDONTWRITEBYTECODE=1 \
  agri_backend/.venv/bin/python -B -m pytest -q tests/test_map_position.py -p no:cacheprovider
node tests/web_location_map.test.cjs
cd agri_web
TMPDIR=/home/jetson/agri_robot/.runtime/tmp npm run build
```

坐标测试覆盖固定基准、车辆参考点、远离中央经线时的真北方位、未知/过期定位与原始 GNSS 不覆盖车体位置。前端测试覆盖无 Key 不发请求、位置更新不重建地图或瓦片、最后位置灰显、跟随、图层替换、错误/超时停请求、隐藏与卸载清理。浏览器联调脚本 `tests/web_realtime.spec.cjs` 拦截全部 API、视频及地图瓦片请求，只使用模拟数据；不可将浏览器模拟数据发送给实车 ROS。

真实 Key 的服务权限、试验地影像清晰度及实车点位对齐，需用户填写 Key 并在收到现场定位后核对。

2026-10-30 软件验证结果：地图坐标、MGX23 速度及设备 API 共 29 项后端离线回归通过；地图状态 8 项、状态通信 7 项、任务栏目 13 项，共 28 项前端离线回归通过；前端类型检查及生产构建通过。对构建产物的隔离浏览器检查通过，覆盖 Key 配置、数字瓦片主机、图层切换、1440×1100 桌面与 390×844 手机布局、展开后急停入口的可见性和点击区域、最后位置灰显、原有安全/相机/任务状态和路径坐标系检查。截图在 `.diagnostics/location-map-browser/*-synthetic.png`，图片与位置均为模拟，不能作为现场影像或实车定位验证。

浏览器验证复用预装 Chromium 与已有 Snap 运行库，在项目诊断目录中运行测试副本；系统和厂商安装文件未修改。回归还修复了原有雷达复选框请求被拒绝后勾选显示未回滚的问题，仅同步前端显示，不改变实际保护策略。运行后端已单独重载以提供新地图坐标字段，未重启 ROS 核心或发出车辆操作。

2026-10-30 缩放与卡顿修复：确认初始实现无有效定位时会随每 2 s 的任务信息刷新重复设置 18 级视野，已离线复现 3 次同值原点刷新触发 3 次复位。现仅初始化一次原点视野，保留人工平移/缩放；首次车辆定位也保留人工缩放级别。瓦片改为拖动期间按 200 ms 限频更新、缩放时及时更新，标记位置变化时复用图标。11 项地图状态测试及前端构建通过；隔离浏览器新增“无定位时缩小地图并等待 4.5 s，跨两轮任务刷新仍保持比例”的检查并通过原有完整回归。本轮仅前端变更，未重启实际服务或操作设备。

本轮只读采样中，本机状态接口约 12–35 ms、设备接口约 22–42 ms、任务信息接口约 102–173 ms，未见秒级后台阻塞；这些数值不代表用户浏览器到 Jetson 或天地图的实际网络耗时。用户电脑上的主线程渲染耗时与真实瓦片网络等待尚未采集，不能将整页卡顿全部归因为网络或声称已完成该电脑的性能验收。

2026-10-30 等高布局验证：按用户要求，宽屏总览地图卡片改为填充与右侧机器人状态相同的高度，增加的空间用于地图画布。前端类型检查与构建通过；隔离浏览器在 1440×1100 下测得两张卡片均高 669 px、地图画布约 446 px，上下边缘对齐；390×844 下画布约 321 px，无横向溢出。展开地图时顶部急停入口仍可见、可点击。本轮仅样式与说明更新，未操作车辆或重启实际服务。
