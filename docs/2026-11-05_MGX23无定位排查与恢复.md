# 2026-11-05 MGX23 无定位排查与恢复

## 现象与原因

用户报告：定位设备已开启，运行统一启动命令后 Web 没有定位数据。随后用户将设备拿到室外。

本次发现三个问题，不能将“设备通电”“TCP 已连接”和“导航定位有效”视为同一状态：

1. 最早启动记录中的 525 个校验正确的 NAVI 帧，定位精度字段全部为 `-1`，没有通过现有 `0 <= accuracy <= 0.5` 导航数据检查；状态字 `0x0A1C0001` 的 READY 位未置位。稍后直连只读采样 4 秒取得 40 帧，仍为精度 `-1`、经纬度 `0,0`、初始化未完成。
2. `mgx23_ws/src/` 已有最新状态字旁路发布功能，但 `mgx23_ws/install/` 中仍是旧版驱动。旧版在精度检查之后才发布状态字，因此导航数据被拒绝时，新的 Web 初始化状态也没有更新。重新构建使实际安装文件与源码一致。
3. 用户重新启动服务并移至室外后，旧 TCP 会话仍显示 ESTABLISHED，却从约 11:15:54 起连续数分钟没有新字节；只读 ROS 订阅同样收不到 `/mgx23/raw` 和 `/mgx23/status`。驱动只在连接关闭或 socket 报错时重连，原先没有无数据超时处理。

早期原始数据：

- `.runtime/mgx23_raw/mgx23_20261105_093020_642463.bin`
- `.runtime/mgx23_raw/mgx23_20261105_111356_292550.bin`

上述数据是当次观测，不能作为设备未来实时状态。

## 修改与加载

修改 `mgx23_ws/src/mgx23_driver/mgx23_driver/mgx23_node.py`：

- 增加正数参数 `receive_timeout`，默认 3 秒。
- TCP 连接成功和每次收到非空字节时记录单调时间。
- 非阻塞接收无数据且超过超时时，关闭旧连接、清空残留帧缓存，由现有重连机制重新连接。
- 该判断仅适用于 TCP。收到字节仅表示传输活跃，位置、姿态、速度仍须通过原有导航数据检查；精度为负值时仍不发布定位。

## 恢复验证与限制

新版加载后短时只读订阅收到真实原始数据、状态字和定位数据；Web `/api/devices` 与 `/api/robot/status` 同时恢复：

- 状态字 `0x005C0002`，READY、PPS_READY、SYNC_READY、GNSS_CONNECT 全部置位，初始化显示成功。
- 定位有效，经纬度约 `36.6502021, 117.0213640`，`map_position` 可用，观测时 `/odom` 年龄约 0.02 秒。
- 原始 NAVI 样本精度字段约 `0.00357`。这是设备报告字段，不是独立测量所得的绝对定位精度，也不证明 RTK FIX 等级。
- 急停仍开启、控制权为空、底盘反馈为零，没有开始导航或执行行驶。

恢复后的连续原始记录：`.runtime/mgx23_raw/mgx23_20261105_112523_936262.bin`。

本次真实设备验证确认重新连接后数据恢复；新增超时分支通过离线模拟 socket 无数据验证，没有人为断开正在工作的实车网络来验证长时重连。没有验证长时间稳定性或独立定位精度。设备必须先输出通过检查的有效导航结果；重连不能代替设备初始化，也不会自动解除急停或恢复任务。
