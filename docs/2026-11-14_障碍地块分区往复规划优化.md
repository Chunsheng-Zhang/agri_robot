# 障碍地块分区往复规划优化

日期：2026-11-14。适用“一键优化规划”（SMART，固定原地转向）。全部结果是合成地形的软件规划预测，未进行实车或真实机具作业验证。

本文保留同日分区块方案的历史过程与数据。用户随后明确允许跨分区访问，当前已用原生条带级TSP与完整Route连接替代本页的分区块2-opt/四状态DP，见[Fields2Cover原生TSP接入与验证](2026-11-14_Fields2Cover原生TSP接入与验证.md)。下文“本次”“新流程”仅指这一历史中间版本，不是当前软件现状，也不是用户要求每区连续完成。

## 问题与依据

旧智能规划把所有作业行放进一个`Swaths`，孔洞两侧的短行也被混在一起进行往复排序，再对散装作业行做局部2-opt。连接只检查能否安全到达，不限制穿越已作业区域，因此会出现障碍附近反复穿插的斜线。仅通过“没有撞到障碍”不能说明作业顺序合理。

本次参考以下原始来源，采用“分解—分区连续往复—通道连接”的结构：

| 来源 | 本次采用的思路与边界 |
| --- | --- |
| [Oksanen & Visala, 2009, Journal of Field Robotics, 26:651–668](https://doi.org/10.1002/rob.20300) | 农田分区、方向搜索与作业顺序应协调设计；不将本实现声称为论文算法的完整复现或全局最优解。 |
| [Höffmann、Patel、Büskens, 2024, Journal of Field Robotics, 41:823–844](https://doi.org/10.1002/rob.22286) | 区分作业轨迹生成、访问顺序和可行连接；不能把几何可连通等同于合理作业路径。 |
| [Mier、Valente、de Bruin, 2023, IEEE Robotics and Automation Letters](https://doi.org/10.1109/LRA.2023.3248439)，[作者稿](https://arxiv.org/abs/2210.07838) | 复用Fields2Cover现有几何分解、条带和图路由组件，保留模块接口。 |
| [Choset & Pignon, 1997, FSR，CMU原始条目](https://publications.ri.cmu.edu/coverage-path-planning-the-boustrophedon-decomposition) | 每个往复分区连续覆盖，再规划分区间访问；该条是基础会议论文，并非期刊。 |
| [Fields2Cover官方分解教程](https://fields2cover.github.io/source/tutorials/decomposition.html)及本地`RoutePlannerBase::createShortestGraph` | 保留分区，不打平；通过地头/分区边界网络连接。当前Python绑定未暴露`createShortestGraph`，项目适配建图后复用原生`Graph2D`，没有修改上游库。 |

使用本机既有Fields2Cover 2.0实现，无需升级系统或切换v3；v3源码核对见[源码分析](2026-11-14_Fields2Cover_v3源码与复杂地块处理分析.md)。没有引入NSGA、PSO或新的可填写策略参数。

## 新流程

1. 按原车长、车宽、旋转中心和安全余量计算完整旋转圆包络，地头宽度仍为`r+0.0001 m`。
2. 工作区使用保守mitre折角偏置。这样绕禁入区拐角时不再沿离散圆弧安排许多微小停车旋转；整条最终路径仍按原完整圆包络校验，净空不放宽。
3. 对每个候选作业方向调用原生`DECOMP_Boustrophedon`，分割线与条带方向平行；核对分区并集没有遗漏安全工作区。
4. 每个分区分别调用`SG_BruteForce`和`RP_Boustrophedon`生成四种起步方案。一个分区的全部作业行连续完成一次，不能与其他分区交错执行。
5. 多分区的换行、换区均沿分区边界网络走，使用Fields2Cover `Graph2D`求通道最短连接；不允许斜穿分区内部抄近路。通道上的重复行驶仍如实计入重复覆盖。
6. 固定分区顺序时，通过四状态动态规划选择各分区方向；比较基础顺序、最近分区顺序和两轮局部分区块2-opt。2-opt仅移动完整分区，不拆散其作业行。
7. 保留原PCA/垂直方向、15°粗搜和±5°/±2°/±0.5°细化；完成预定比较，按原0.5/0.3/0.2固定评分选完整路径，没有新增候选上限、主动时间预算或最低覆盖率门槛。
8. 保留同XY不同航向的停车标记、跟踪器分段对齐、安全仲裁、人工取消和外层120秒异常保护。

原生`Graph2D`采用全点对最短路径。适配层只把通道角点和交汇点放进图，作业行端点投影到边上，在查询时拼接首尾边；避免图规模随密集条带端点增长而造成三次方计算量。分区缝按10微米归并，20微米内的连接数值短枝清理后仍执行完整净空检查；这些是几何运算容差，不是定位或行驶精度承诺。

田外人工入口的锚点按完整半径区域求得，可能在额外0.1毫米数值内缩之外。本次改为用入口自己的安全路由计算参考距离，避免全部候选被错误拒绝。入口仍只影响规划选择与长度评分；明确开始覆盖后仍是原来的直接单点接近覆盖首点→航向对齐→路径跟踪，不先驶向入口。

## 同一批地块的前后比较

旧结果来自`.diagnostics/terrain_planning/summary.json`及其`evidence_dir`指向的真实保存路径，新结果位于`.diagnostics/terrain_cell_routing/`。使用相同边界、固定原点、0.8 m幅宽、0.2 m车宽、0.45 m车长、0.05 m余量、0.1 m路径采样和0.15 m评价网格。每版独立完整搜索，因此选定角度允许变化。

| 合成地块 | 总长度 m：旧→新 | 预测覆盖率 %：旧→新 | 预测重复率 %：旧→新 | 停车转向数：旧→新 |
| --- | ---: | ---: | ---: | ---: |
| 单禁入区 | 805.75 → 752.44 | 97.95 → 98.67 | 10.60 → 3.57 | 168 → 100 |
| 双禁入区 | 1027.63 → 941.67 | 98.45 → 98.18 | 9.36 → 3.03 | 331 → 122 |
| 凹地块＋禁入区 | 718.11 → 699.17 | 98.65 → 98.94 | 7.10 → 4.58 | 178 → 107 |
| U形凹地块 | 540.20 → 545.97 | 97.55 → 98.73 | 4.88 → 4.46 | 80 → 107 |

不保证每项指标同时改善。例如双障碍覆盖率下降约0.27个百分点，重复率降低约6.33个百分点；U形选择了覆盖更高、但略长且转向更多的路径。这符合用户指定综合评分；本轮没有把时间或转向次数偷偷增加为优化目标。

11种地形中10种完成，0.2 m窄连接区因无法容纳完整旋转包络而失败；未遗漏另一侧区域冒充成功。可规划新路径的完整净空越界长度、穿越原始禁入区长度均为0。三个障碍样例的实质横向交叉数分别从5/3/1降到0/0/0。该统计排除距离任一线段端点1 mm以内的接触，以及夹角正弦小于0.001的近共线数值相交；边界通道重走仍进入重复覆盖率，不宣称路径完全无重复。

原始坐标不分别归零；所有字段、轨迹与评价继续使用统一map原点。预测覆盖率不等于实车跟踪精度或实际农艺效果。

每次新规划的`paths/optimization.json`记录`cell_count`、`cell_visit_order`、`cell_swath_ranges`、`cell_reentries`、`swath_length_m`、`transition_length_m`和`connection_policy`。`cell_reentries:0`表示分区的作业访问不回入，不代表边界通道没有重复经过。`working_length_m`仍是整条正式路径长度，含全部连接；新增`swath_length_m`才是纯作业行长度，两者不能混淆。设置入口时再加`entry_length_m`得到原计分总长度。

最佳路径的`planning.path_details.cell_polygons`保存按分区ID索引的二维轮廓，`planning.policy_version=3`。优化报告仍为`schema_version=2`，兼容旧报告与保存路径；历史路径不改写。普通“生成覆盖路径”、四种原生曲线和回形仍走原有流程，本次没有把它们改为原地转向。

## 使用与验证

构建`agri_path_planning`后，在正常停车、任务结束时按当前设备开关和配置重启原有核心；本次没有自动重启正在运行的服务。新代码需要点击“一键优化规划”重新生成，加载已保存旧路径不会自动重新规划。

```bash
cd /home/zhang/agri_robot
source scripts/setup_environment.bash
mkdir -p .runtime/tmp .runtime/ros
export TMPDIR="$PWD/.runtime/tmp" ROS_LOG_DIR="$PWD/.runtime/ros"
cd agri_robot_ws
colcon build --symlink-install --packages-select agri_path_planning
```
