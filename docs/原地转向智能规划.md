# 原地转向智能规划

更新：2026-11-13。此文描述当前“一键优化规划”，替代历史的四种覆盖形式、自动地头区间和能源代理组合搜索。手工“生成覆盖路径”继续保留；原生曲线与回形路径不因此重写。

## 使用

1. 在 Web“全覆盖规划与跟踪”选择或新建任务，编辑边界与禁入区。
2. 在“规划与路径跟踪参数”填写机具有效作业宽度、车体包络长宽和原地转向安全余量，按需要设置跟踪速度及前视距离。
3. 点击“保存任务”，选择“全覆盖作业”模式，点击“一键优化规划”。规划本身不会取得运动控制权。
4. 查看推荐方向、最小安全地头、总长度、覆盖率、重复覆盖率、原地转向点数及候选评分；地图的内缩线与报告采用本轮自动地头。
5. 如需以后复用，明确点击“保存规划路径”，才会进入左侧任务下的路径列表。“加载此路径”与“前往起点并开始覆盖”仍是两个独立操作。

智能策略的手工输入集中在物理参数与跟踪参数。条带顺序、人工方向、人工地头、最小转弯半径、四种原生曲线和允许倒车，继续服务于手工“生成覆盖路径”；一键优化不读取这些选项，固定前进直线＋停车原地转向。任务中保留这些参数便于两种按钮分别使用。

## 几何与最小安全地头

用户确认先沿用估计值并保留修改入口：

| 参数 | 初值 | 修改位置 |
| --- | ---: | --- |
| `operation_width` | 沿用本任务 | Web“机具有效作业宽度”，单位m |
| `robot_length` | 0.45 m | Web“车体包络长度” |
| `robot_width` | 0.2 m | Web“车体宽度 robot_width” |
| `rotation_safety_margin` | 0.05 m | Web“原地转向安全余量” |
| `rotation_center_x/y` | 0 / 0 m | 任务JSON或统一YAML，按base_link到包络中心的偏移配置 |

L/W应包住车辆及随车机具实际外伸；有效作业宽度与物理包络宽度含义不同。base_link的旋转中心默认在矩形中心。规划不根据当前RTK定位漂移自动修改车辆尺寸。

```text
r = hypot(L/2 + abs(cx), W/2 + abs(cy)) + safety_margin
headland = r + 0.0001 m
```

缺省r约0.296221 m，地头约0.296321 m。0.0001 m是几何运算数值裕量，不是定位精度承诺。这个宽度是当前完整圆包络模型的安全内缩值，不是任意安装方向、机具姿态下经过证明的实际最优地头。

地块外边界向内缩、禁入区向外扩。沿所有行驶段与转向点使用同一个完整圆包络检查，比只在转角检查更保守；因此某些窄区即使直行能通过，也可能在本策略下不可行。若内缩区域分裂且无法安全连接，整轮失败，不穿越禁入区或把不完整路径当成功。

作业幅宽大于车体包络时，圆盘评价足迹可能覆盖到中心线不能到达的边角，但不代表机具没有实体尺寸；物理机具仍应体现在长宽包络中。尺寸与余量必须在实车实验前核对，变化后保存任务、重新规划。

统一缺省配置仍为`agri_robot_ws/src/agri_bringup/config/system.yaml`及`config/jetson_system.yaml`。新任务可继承缺省，任务级值优先并随运行归档；旧任务/实验快照不回写。雷达独立车体尺寸配置不由此自动改变。

## 路径生成与有限角度搜索

- 复用Fields2Cover的条带生成器`SG_BruteForce.generateSwaths`和`RP_Boustrophedon`往复式排序。
- 首轮比较边界PCA主方向、垂直方向以及0–165°的15°网格，角度以map东向为0、逆时针为正，按180°周期处理。
- 再围绕当前较优方向比较±5°、±2°、±0.5°，完整执行预定细化比较。
- 换行使用内缩区中的安全直线连接；凹地块/孔洞采用可视图最短直线折线。这里仅处理已知边界与禁入区，不是雷达动态绕障。
- 对有改进空间的访问顺序尝试有界局部2-opt：保留每条作业行，反转局部行块及方向，以减少连接长度；基础方案与改进方案都生成完整路径，最终按同一综合评分选。
- 每个折线转角保留停车/原地旋转动作，不用半径为0的Dubins或Reeds–Shepp代替。

2026-11-13后续调整：取消候选数量上限与45秒搜索主动截断，完整执行上述有限的方向与局部行顺序比较，再选择得分最低者。旧任务中`optimization_max_candidates`、`optimization_time_budget`读取时忽略，新任务/API默认值/快照不再写入，历史文件不回写。只保留当前最佳候选的完整几何和所有候选的评分记录，避免累计保存大量路径而提前结束搜索。

网页顶部“智能规划进度”显示准备、粗搜、细化或最终校验阶段，已比较候选数、可执行候选数、阶段方向完成数/总数、当前角度和已用时。进度条只代表当前阶段的方向处理进度，不代表总耗时预测或完成率保证；切入细化阶段时计数重新开始。可随时点击“取消规划”。状态过期时隐藏旧进度，任务重新生成/加载或切为手工规划时不显示上一轮进度。

ROS仍保留`coverage_adapter.planning_timeout`外层异常超时保护，统一YAML缺省120秒。若计算超过该值，任务失败并停止发布可执行结果，不返回搜索中途的较优路径；人工取消也不会发布迟到结果。复杂地块需要更久时可在实际启动参数文件中调整这个异常保护值，不能将其解释为45秒搜索预算。每条路径采样点数、地块几何复杂度及评价网格的独立资源检查仍保留，失败原因如实记录。

这是有限角度、有限局部行顺序集合中的加权择优，不是全局最优、Pareto集合或论文中的HANS/NSGA算法。正常结束的报告新增`search_complete:true`、`candidate_limit_enabled:false`和`search_time_limit_enabled:false`，`possible_count`等于实际比较的完整候选数。历史报告按其原有预算口径显示，不补写完成标志。


## 评分与质量口径

令A为整田面积（扣除禁入区，包含地头），W为用户机具有效幅宽，L为完整平移路径长度，C/O为覆盖率/重复覆盖率的百分数：

```text
L0 = A / W
J = 0.5 × (1 − C/100)
  + 0.3 × O/100
  + 0.2 × L/(L + L0)
```

选J最低的可执行完整方案；同分依次优先覆盖率较高、长度较短者。C、O、长度归一化均为无量纲项，权重固定，界面不再让用户编辑多套策略权重。没有最低覆盖率硬门槛。

C为至少经过一次的面积/A，O为至少经过两次的面积/A。不是“多走长度比例”，也不是“重复面积/已覆盖面积”。漏覆盖按同一整田分母计算；地头单列统计。所有候选采用相同圆盘等效机具足迹和同一网格，输入`quality_resolution`默认0.05 m，大地块超过网格单元预算会自动加粗并记录实际间距。候选评分与最终报告使用同一实际网格。

智能规划的条带间距与评价幅宽均使用W，不自动改幅宽，不再单设第二个评价幅宽输入。历史手工任务若有`evaluation_width`仍按旧口径只读/执行；新智能规划明确忽略它，并标注`width_source=operation_width_effective`。

L包含全部作业行、换行及绕已知禁入区的连接。停车原地转向的平移长度为0；起点接近段独立，尚未纳入评分。此版不优化能源、作业时间或土壤影响。所有平移连接都按机具开启估计，当前没有真实机具开关数据，不将几何覆盖率称作实测农艺作业质量；圆盘模型也不增加原地旋转的独立作业面积或重复次数。

## 跟踪、暂停和数据

ROS接口保持`/reference_path`（`nav_msgs/msg/Path`、map坐标）。规划进度经独立后台进程传至`/planning/status.search_progress`，每0.2秒随状态心跳发布，网页复用`/api/devices`刷新，不另建运动通道。原地转向标记为相邻两个相同XY、不同入/出航向的Pose；保存文件中保留这些Pose与`motion_signature`，不能在其他工具中随意去重。跟踪器读取标记，将路径拆为独立直线段，进度投影与前视点不会跨过未完成的原地转向点。

1. Pure Pursuit沿当前直线段前进，接近段尾减速。
2. 中间段在剩余长度和端点距离均进入`min(0.05 m, completion_tolerance, 当前段长/4)`后输出零速度、切到下一段的ALIGNING。
3. 保持零线速度/零角速度，使用新鲜定位检查约0.5秒的位置稳定，漂移超过2 cm重新计时。
4. 线速度持续为0，按下一段航向原地旋转；默认角速度不超过0.3 rad/s，同时受任务上限约束。
5. 航向误差进入±10°、新鲜定位保持约0.5秒且位置稳定后，进入下一段前进。对齐超时30秒故障停车。

这些稳定性检查来源于定位，不等于独立轮速反馈证明物理停稳。暂停/继续保留段号和进度，并重新对齐；停车等待阶段恢复会重新计时。急停、定位故障、控制权及速度安全检查仍由现有链路处理，不自动恢复。多点导航逻辑不变。

```text
data/experiments/<本轮>/
  config/mission.json                  人工幅宽、车辆尺寸、余量及任务快照
  paths/coverage_*.json                完整入/出航向、转向标记、旋转包络、有效参数、姿态指纹
  paths/optimization.json              schema_version=2，角度/顺序候选、固定权重、评分、拒绝原因
  tracks/track_*.csv/.json             正式平移跟踪，元数据包含point_turn_indices
  tracks/alignment_*.csv/.json         起点/中间原地转向/恢复对齐的独立记录
  analysis/coverage_quality_plan.json  本轮规划预测，统一有效幅宽与安全地头
  analysis/coverage_quality_report.md  结束后的作业质量、规划规则与本轮跟踪汇总
```

`paths/optimization.json`仍通过`GET /api/runs/{id}/optimization`查看，独立优化接口仍为`POST /api/missions/{id}/optimize`及ROS`/planning/optimize`（Trigger）。保存、加载检查相同任务版本、固定原点、完整旋转净空和姿态指纹；修改尺寸、余量或幅宽需重新规划。历史v1优化报告保留原解释，不改写既有路径及实验数据。
