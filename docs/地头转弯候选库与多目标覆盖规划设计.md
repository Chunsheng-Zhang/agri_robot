## 1. 当前实际能力

| 层次 | 当前 Web / 项目适配器 | 底层已有但未完全接入 |

不能把“三种排序×两种方向×两种曲率”解释为12个独立规划算法，也不能把 Dubins 连续/非连续曲率当成 U/Ω/鱼尾形状菜单。SPIRAL 是条带访问顺序，不保证几何路径就是沿边界逐圈内缩的连续螺旋。

2026-11-09 补充离线核对：直接调用本地已安装 Fields2Cover 的 `genSortedSwaths(...,0)`，不创建ROS节点、不发布路径。已安装 `RouteMode` 默认 `spiral_n=4`，项目适配器未覆盖该字段。8条平行条带时，牛耕顺序为1→2→3→4→5→6→7→8，SNAKE为1→3→5→7→8→6→4→2，SPIRAL(4)为1→4→2→3→5→8→6→7；两者并非普遍相同。仅2条时均为1→2，仅3条时SNAKE与SPIRAL(4)均为1→3→2，确实会出现相同顺序。即使顺序不同，平行作业段的位置仍相同，需通过编号/方向和连接转弯区分。为避免名称歧义，说明时称“隔行蛇形”和“分组螺旋式排序”；尚未修改网页选项名称。

自动方向搜索使用条带长度目标，不是对完整可行路径的时间、能源、土壤影响进行联合寻优。覆盖质量评价目前是规划后的分析，没有反馈到规划搜索中。

## 3. 候选库

候选是由“出口位姿→入口位姿”现场生成的带方向轨迹，不是事先画好的固定 XY 模板。起终位置、航向、行间距、跨行数、边界夹角、地头形状和禁入区均参与生成。

| 候选 | 基本构成 | 初期执行能力 |
| --- | --- | --- |
| U 型 | 同向转弯圆弧/过渡曲线，必要时加中间直线；可相邻行或跨行 | 前进候选，优先实现 |
| Ω 型 | 向外展开的多曲线连接；可容纳较小行间距但通常需要较大外侧空间 | 前进候选，优先实现 |
| 鱼尾 | 显式前进—倒车—前进等换向序列；工程上常见两次换向，需记录实际段序列 | 可先预览，完成倒车/换向/保护后才开放执行 |
| Flat / Hook / 非对称连接 | 宽地头、斜边界或非对称入行的补充形状；统一约定命名 | 后续按需求扩展 |
| 转向—平移—转向 | 履带/差速底盘的分段原地旋转与移动 | 单独运动原语，不能以 Dubins 半径设0替代 |
| 优化式连接 | 模板失败后使用状态格点/Hybrid A* 初解及差速轨迹优化 | 后续补充，不替代基础模板与可行性验证 |

Dubins 最短曲线可能已呈 U 或 Ω 外观；显式候选库应能够强制生成、分类和保留多个可行备选，包含非最短但更易跟踪的连接。Reeds–Shepp 是产生含倒车连接的工具，不等于所有输出都可称“鱼尾”；需要模式标签和换向结构检验。

每个候选保存：`type`、起终 SE(2) 位姿、`segments`、方向、机体 yaw、采样点、曲率、期望速度、停车/换向点、机具开关、长度、预测时间/能耗/土壤成本、最小净空、可行性及拒绝原因、模型/参数版本。左右对称解和跨行方案都应进入候选。

以轨迹全程车体与机具扫掠包络验证边界和禁入区，不能只验证中心线。对履带转弯使用含滑移影响的标定约束；理想差速关系 `v_R=v+bω/2`、`v_L=v-bω/2` 只作为基础，不能当履带—地面无滑移真值。限制履带速度/加速度、机器人加速度、角加速度和横向加速度。原地旋转虽不需要平移半径，却可能增加转向电耗和土壤剪切。

## 4. 联合优化变量与目标

建议决策变量为 `z=(θ, δ, h, π, d, τ, v, u)`：作业方向、条带横向偏置、地头预留宽度、条带访问顺序、各条带方向、各次连接类型/跨行选择、速度计划、机具作业状态。已有作物行约束时固定方向，已有机具幅宽不得为了提高指标任意放大。

按需要加入区域分解与单元访问顺序；第一版先在单地块、固定分解下验证，避免同时改变所有算法。

完整评价向量可采用：

`min F(z) = [1-C_work, O_work, T, E, L, D_soil]`

同时报告可作业区域/地头、转弯/直线、前进/倒车等分区。所有几何值沿用固定原点。

### 4.1 作业覆盖与重复覆盖

设 `A` 为地块扣除禁入区后的任务要求作业区，`W_on` 为机具开启段扫掠并集，`n_work` 为作业经过次数：

- `C_work = area(A ∩ W_on) / area(A)`。
- `O_work = area({q∈A: n_work(q)≥2}) / area(A)`。
- 内部区、地头区和整田分别统计；未安排地头作业不能通过仅改变分母宣称整田全覆盖。

当前 `coverage_geometry.py` 可复用作候选数值评价器，但真实机具模型/偏置和作业开关需要扩展。目前“全部连接转弯也假设机具开启”的评价约定必须按版本逐步升级，不静默改写旧报告。

覆盖下限、禁入区、运动能力和定位/安全权限作为约束。例如 `C_work≥C_required`，阈值由任务和可达性决定，而不是直接固定任意99%。无可行路径时返回缺口区域与原因，不以少作业换取更低时间/能耗。整田不可达面积应如实披露。

### 4.2 时间

按经可执行速度规划得到的 `ΣΔs/|v|` 加入换向停车、机具启停、入行对齐以及原地转向时间；原地转向按角位移和角速度/加速度积分。不能把全程长度除以一个速度作为最终时间模型。保留现有跟踪±1 m/s、±1 rad/s限幅，并让跟踪器实际使用经过审核的分段速度上限，才便于验证计划时间。

### 4.3 能源

优先采集电池母线电压与电流，以放电方向为正定义 `E=∫U(t)I(t)dt/3600`（Wh），明确是否为净能耗或仅正向耗能。记录时间同步、缺测、驱动与机具/辅助用电边界。

目前只有电压等数据，不能声称已测得电能。补充电流/功率计或BMS接口后，分别标定直行、曲率、原地旋转、换向、载荷/地面条件。没有电流时可用已标定代理模型评价并标注“预测”，未标定仅使用“能耗代理成本”，不能填成实测 Wh。坡地再加入高程/坡度。

### 4.4 土壤影响

用两条履带真实接地包络生成 `n_track(q)`，与机具足迹 `n_work(q)` 分开。

- 可先报告受碾压面积占比 `area({n_track≥1})/area(A)`、重复碾压面积占比、次数分布。
- 代价可用 `D_soil = ∫A g(n_track(q), 土壤属性, 载荷, 接地压力)dA + λ_s J_shear`。
- `g` 为非线性压实风险模型；`J_shear` 为另行标定的履带转向剪切代价，不将其误称已有 SoilFlex 结论。
- 真实压实验证需土壤含水率、初始状态、履带几何/压力分布，以及容重或贯入阻力等独立测量。未做土样试验时只报告通行面积和风险代理，不能把它们称真实压实率。

受碾压面积与重复经过不是同一目标；固定车道可减少新土受扰面积却增加车道内经过次数，需结合风险模型和农艺边界取舍。压实成本依赖历史通过状态，不能用一张静态转弯长度矩阵替代全局评价。

## 5. 求解策略

1. 使用现有 Fields2Cover 生成方向/偏置/内缩候选及条带，不重写条带算法。
2. 给每条有向条带出口与可达入口构造候选边：多种 U/Ω/鱼尾/跨行连接，执行硬约束过滤。
3. 初期以三种现有顺序、自定义跨行顺序及局部交换作为路线候选；从全程累计状态评价覆盖、通行影响、长度与时间。
4. 先做有限候选枚举/局部搜索与 Pareto 非支配筛选，建立可信基线；在大规模变量下再接 NSGA-II（少量独立目标）或有约束 NSGA-III / MOEA/D（5–6个独立目标），使用排列保持的交叉/变异和可行性修复，不直接把通用连续编码用于条带排列。
5. 可用覆盖/安全为硬约束，先优化时间、能耗、土壤风险，同时展示长度与重叠，检验目标相关性；真正保留全部6目标时需评估解集质量与计算预算。
6. 归一化时固定参考尺度、记录权重与模型；输出多个折中方案，不声称所有指标能够同时达到各自最小值，不把一次启发式结果称全局最优。
7. 基于参考点、约束或用户偏好选择一条方案；只有被明确选中的路径才能成为 `/reference_path`，不让后台候选逐条覆盖正在使用的参考路径。

层间需迭代：方向影响条带数与转弯；排序影响跨行连接；转弯与速度影响时间/能源/土壤。局部每次选最短转弯，不保证全田最优。边缓存须包含地块/禁入区、起终位姿、机体/机具、运动约束及模型版本。

## 6. 与本项目集成

在 `agri_path_planning` 中增加小而清晰的模块：`turn_library`、`candidate_evaluator`、`multiobjective_planner`；计算密集部分用C++复用Fields2Cover，Python保留任务接口/编排。可以先直接使用本地C++API，不为研究模块强制引入复杂插件框架。

新规划流程建议先保持旧模式为 baseline；优化模式独立计算候选，再由统一适配器校验固定原点、路径指纹及当前控制状态后发布选中路径。

现有 `nav_msgs/Path` 可继续做显示，但无法可靠表达倒车、原地转向、机具状态、换向停车和分段速度。需要在 `agri_interfaces` 增加带段类型的轨迹接口，最少包含 `pose`、`segment_id`、`motion_type`、带符号速度、角速度限制、机具开关和停车标志；机体航向与倒车行进切线不得混淆。新跟踪状态机执行前进/倒车/停车换向/原地转向，安全输出仍走唯一safety入口。

当前前方180°雷达保护不覆盖倒车方向。增加鱼尾的执行能力时必须明确后向安全方案；在此之前候选可以预览，但不能绕过前进控制器的拒绝检查。

Web 在“规划与路径跟踪参数”旁增加独立的“转弯策略/多目标优化”配置，给出可选转弯、能力限制、约束/偏好和候选方案对比。“规划作业质量评估”继续负责评价幅宽、网格、指标和报告，不把所有算法参数混在质量卡片里。

建议新增本轮 `planning/` 或现有 `paths/` 下的候选子目录，保存所有候选指标、模型版本、随机种子、预算、失败原因、Pareto 集、选中原因、分段轨迹与来源摘要；正式执行的数据仍放原 `tracks/telemetry/analysis`，接近/对齐分开。

## 7. 实施顺序与论文验证

- A：可预览和比较的 U/Ω 前进候选、跨行顺序、净空校验；复用现有前进跟踪。先补独立地头作业规划，解释整田覆盖缺口。
- B：有限候选多目标筛选与方案对比；时间/长度/覆盖/通行风险先形成可重复基线。
- C：带方向分段轨迹、换向与倒车跟踪、后向安全，再开放鱼尾执行；原地旋转作为独立能力选项。
- D：电流/功率采集与模型标定、真实土壤测量；再评价NSGA-III等大规模优化和履带剪切模型。

用于发表的对比应统一地块、幅宽、起终条件、机具开关、速度限制和计算预算：现有规则+Dubins baseline；仅候选库；仅路线优化；候选库+联合优化；移除能源项/土壤项的消融。报告多次重复、优化随机种子、置信区间、失败/不可达率、计算耗时、解集质量，以及任务完成后的实际跟踪/时间/电耗和土壤验证。仿真、预测代理和实测必须区分。论文贡献应围绕履带适配、联合模型及实证，不以“加入NSGA名称或几种图形”本身宣称创新。

## 8. 用户收敛后的首版方向评估（2026-11-09）

本节替代前文完整研究方案中“首版就同时优化时间与土壤”的范围；长期模型可以保留，但当前用户明确先不考虑作业时间和土壤影响。本节最初为评估，后续已授权实施有限搜索版本，现状以文首链接为准。

### 8.1 首版功能与边界

1. 在牛耕、隔行蛇形、分组螺旋式排序之外，新增名为“回形”的覆盖形式。用户后续明确执行方向改为由内向外，现已实现；几何仍从外轮廓逐层内缩构造，再由最内侧可行轮廓向外访问。优先复用现有几何缓冲/Fields2Cover组件，不重写通用多边形偏置算法。最外层需根据机具有效幅宽、车体包络及净空确定偏置，不能让车体中心直接沿外边界行驶；圈间距受真实作业幅宽约束。
2. 回形需要处理角部平滑、禁入区外扩、内缩分裂、多圈间连接及中心剩余区补作。不能简单将多个闭环首尾连直线，否则可能穿越禁入区或漏掉中心；不允许以重复首尾坐标表达原地转向，因为当前Polyline会移除重复点。
3. 候选库初期按U、Ω、鱼尾三类组织，左右转镜像与跨行距离为候选参数。U/Ω可以先用于前进执行；鱼尾可先实现候选生成与预览。启用其执行前仍需方向/换向轨迹、倒车控制和后向安全，不能把含倒车路径强行传给现有前进Pure Pursuit。
4. 自动地头预留宽度增加独立的手动/自动策略，保留手动设置和现有任务默认行为。自动模式在上下界与有限候选范围内联合搜索地头宽度、条带顺序、转弯类型；最佳宽度取决于地块、底盘、机具及目标，不等于固定2R或统一最小值。
5. 一键规划作为新增按钮，与原“生成覆盖路径”并存。原按钮保留既有参数驱动行为；新按钮比较回形及平行条带方案、起始端/方向、允许的作业方向、访问顺序、转弯与地头宽度，选择可行候选内评分最佳者。已有作物行约束时方向固定，不能为了降低评分跨行作业。
6. 新按钮仅规划，不自动取得控制权或开始跟踪。候选计算过程中不向 `/reference_path` 轮流发布备选；选定后统一校验并发布最终路径。保留模式/原点/指纹与唯一safety速度入口。

### 8.2 地头宽度和整田覆盖的关系

地头是可转弯空间，也可能是待作业区域。调整内缩宽度后，不能只比较变化了分母的内部区覆盖率；所有方案均按同一固定地块扣除禁入区的整田分母评估，内部区指标仅辅助展示。

平行条带候选应补充必要的地头轮廓作业环线，否则增加地头宽度通常只是缩小内部作业区。回形方案本身覆盖轮廓区，但中心和角部仍需检测补作。允许混合“外圈回形＋内部条带”作为后续自然扩展，第一版可先将完整回形与带地头作业的条带方案进行比较。

自动宽度最初采用单一标量，便于沿用现有接口；按边界局部设置不同宽度属于后续扩展，暂不引入。

### 8.3 能耗代理建议

以下数值是尚未标定的工程起始假设，不是从论文测得的本车参数，也不作为Wh或J输出。后续均放入可配置的模型版本中：

- 前进直线：1.0相对成本单位/m。
- 曲率达到参考曲率时的前进转弯：1.5单位/m；较缓转弯在1.0与1.5之间按曲率平滑变化。
- 倒车直线：1.3单位/m。
- 换向：每次额外0.5相对成本单位。

统一示例：`E_proxy = Σ k_dir[1+0.5(|κ|/κ_ref)^2]Δs + 0.5N_switch`，其中前进 `k_dir=1`、倒车 `k_dir=1.3`，`κ_ref` 为固定底盘参考曲率，所有候选保持一致。运动段互斥计费，倒车转弯通过两个因子计一次，不另重复叠加整段距离。

倒车比前进更贵是本阶段人为偏好假设，并非普遍物理定律。论文支持结合运动类型及车辆条件建立成本，不支持无标定地认定固定系数对所有履带、地面和载荷都成立。当前执行候选均前进时，倒车项应为0，不为了展示差异伪造倒车能耗。

第一版不加入原地旋转候选，因此本代理模型不计算其能量。以后增加时需另按转角/角速度等建模，不能因平移距离为0而给出0能耗。

### 8.4 权重与可行性建议

采用“约束优先＋归一化评分”的简单方式：

- 硬约束：全过程包络不越界/不穿禁入区、控制器可执行、达到明确的整田覆盖要求。
- 初始可调评分：`J = 0.35·O_norm + 0.45·L_norm + 0.20·E_proxy_norm`。
- 覆盖率通过任务下限及必要的分层优先比较体现，不让优化器用大面积漏作换取短路径。覆盖目标例如98%只可作为讨论示例，须结合不可达角部、网格敏感性与任务要求确定，不在本次评估中改为项目默认值。
- 重叠、长度及能耗参考尺度必须固定记录并用于所有候选。不能直接把百分数、米和相对能耗相加，也不能对不同候选单独归一化。
- 上述0.35/0.45/0.20是针对“覆盖质量优先、能耗暂为粗略代理”的工程建议，不是任何一篇论文给出的通用权重。论文依据的是目标和归一化/约束思路，最终权重需敏感性分析及实车标定。长度和能耗代理相关，需在报告中披露，避免以增加两个权重虚构两个完全独立目标。
- 无候选满足覆盖和可执行约束时，返回最佳未达标预览、缺口图和拒绝原因，但不得标为可执行最优路径；正常模式仍可保留原手动规划入口。

可先进行粗到细的方向/宽度候选搜索、缓存转弯边、整条路径评估，再加局部交换改进。当前目标和有限模式没有必要一开始引入大型进化优化器。最优仅指本次搜索空间、模型、权重和预算下的候选最优，不宣称连续空间全局最优。预算耗尽须标明搜索未完成，具备进度和取消操作。

### 8.5 界面与验证建议

- 原“规划与路径跟踪参数”继续放作业方向、人工模式、速度与控制参数。
- 新增独立“智能规划策略”区域：启用的覆盖形式、转弯候选、自动/手动地头宽度及上下界、优化偏好与高级权重。能耗模型初值可折叠。
- “规划作业质量评估”显示覆盖/重叠/长度/能耗代理、最终地头宽度、选定模式和转弯数量、候选对比及拒绝原因，说明代理数值不是实测电量。
- 先用矩形、狭长、凹形、带孔洞地块和会内缩分裂的地块离线验证回形及连接；随后隔离ROS验证参考路径、控制方向与跟踪可行性；不改变实车控制逻辑后直接上线。
- 在相同地块、幅宽、净空、起终条件下，将原手动路径作为候选基线，比较不同权重与能耗系数的排序稳定性。整田图上标注条带序号、方向及转弯类型，便于识别模式差异。
