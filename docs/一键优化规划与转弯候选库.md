2026-11-09。在现有Fields2Cover/OpenNav、回形和前进式Pure Pursuit基础上增加有限候选搜索。本轮完成软件实现及隔离测试，尚未做实车性能对比；不把规划预测当作实测质量提升。

## 1. 网页操作

在“全覆盖规划与跟踪”选择或新建覆盖任务，保留边界、禁入区、幅宽、半径及跟踪参数。新增独立“智能规划策略”卡片：

1. 选择地头策略：“自动比较”由系统估计范围并细化较优宽度，不再输入最小/最大宽度；“使用人工宽度”严格采用“规划与路径跟踪参数”里的“地头预留宽度”。
2. 一键规划固定比较牛耕、蛇形、螺旋、回形，不再提供“覆盖形式候选”筛选。方向可保留指定方向，或比较指定方向及其垂直方向。转弯在“规划与路径跟踪参数”统一选择Fields2Cover四种原生形式；“允许倒车”默认关闭，需倒车时显式勾选并保存。存在作物行约束时用固定方向。
3. 日常无需设置覆盖率要求；高级权重与能源系数仅在实验调参时调整。
4. 点击“保存任务（含优化策略）”，明确选择“全覆盖作业”模式，再点击新增“一键优化规划”。原“生成覆盖路径”继续按人工参数运行。
5. 查看“规划作业质量评估”中的选定形式、地头宽度、路径长度、能源代理、候选对比和拒绝原因。覆盖率继续显示，但不设置最低门槛；净空、可执行性检查失败或计算异常仍会拒绝路径。

用户于2026-11-09明确删除覆盖率约束，原“整田最低覆盖率”输入及默认95%门槛已移除；旧任务/导入文件里的`optimization_min_coverage`会被兼容丢弃，不必逐个修改任务，不回写历史快照。其他自定义参数继续生效。

规划不自动开始行驶、不复位急停、不取得控制权。实际开始仍使用原覆盖任务开始流程。任务原始参数不回写；本轮选中参数随路径保存，地图内缩轮廓和质量报告使用选中宽度。

## 2. 搜索内容及限制

- 平行条带：Fields2Cover生成条带，比较牛耕、蛇形、分组螺旋（组大小4）的两种起始变体。
- 回形：沿用由最内侧可行轮廓向外的CONTOUR，具体见[回形路径规划](回形路径规划.md)。它不等同于分组螺旋条带排序。
- 自动地头分两阶段：先依据几何范围和原生曲线包络建立粗候选，再在当前评分较优宽度两侧二分细化。地块几何上界通过含禁入区的逐步内缩估计，并留出车体/作业中心线空间；初始上界还受原生转弯包络加一幅宽工程余量限制，避免大田直接预留巨大地头。初始无完整可行解时，可有界扩展至几何上界。
- 原生包络采用任务选定的Fields2Cover曲线、同一个最小转弯半径、曲率变化约束和倒车许可，仅探测不同条带间距，不恢复半径倍数或U/Ω/鱼尾分类。范围只是估计，每套完整路径仍须通过净空、禁入区和方向检查；人工模式不探测、不细化，不可行时失败，不偷偷加宽。
- 默认24套预算会保留一部分用于细化；每次细化宽度继续比较四种形式，实际执行数量受预算约束。宽度细化停止尺度为作业幅宽的1/10并限制在0.02–0.1 m，是计算分辨率，不是地头可行性证明或跟踪精度。选路仍沿用重复覆盖/长度/能源代理评分，不新增覆盖率门槛或惩罚，不保证全局最优。
- 自动方向仅比较指定方向及其垂直方向，不等于手动按钮中的BRUTE_FORCE角度搜索。
- 默认最多24个完整组合、搜索45秒；可调整至最多128个、90秒。预算到期后对选中路径完成最终统计，另有20秒细网格预算和节点总超时；不再进行覆盖率门槛筛选。取消后不发布迟到结果。
- 24个指完整路径组合数，例如覆盖形式＋地头宽度＋方向＋起始变体，不是路径采样点、条带或转弯数；失败的几何方案也计入尝试预算。45秒限制的是搜索计算，不是车辆作业时间，也不要求必须算满45秒。最终质量统计、调度和通信另需时间，不能保证总响应不超过45秒。两项已移入折叠“高级：计算限制”，通常保持默认或任务已保存值即可，无需每次填写。
- 2026-11-10起移除`optimization_patterns`界面、默认值和API字段；旧ALL/STRIPES/CONTOUR读取时均丢弃，一键固定纳入四种覆盖形式。预算和几何失败可能使部分组合未完成，不宣称穷尽搜索。人工规划的“条带作业顺序”继续可选，历史快照不回写。
- 旧任务的`optimization_headland_min/max`同样兼容读取并丢弃，不再限制新自动搜索；新路径与`optimization.json`中的`headland_search`记录估计范围、原生参考包络、粗/细化宽度和次数、选中值及方法版本。旧报告仍按原快照口径只读，不重新计算或回填。保存/加载新路径时保留本轮搜索元数据，地图和质量报告共用实际选定宽度；不会把选中值写回任务人工配置。
- 条带方案增加可行的地头轮廓补作及连接，整田分母不因预留地头而缩小。生成失败或净空不足会拒绝整个方案，不拼接不可行直线或发布部分路径。
- 每条连接按选定原生曲线和固定最小半径生成，再对完整参考路径评分；不枚举半径倍数或按U/Ω/鱼尾分类。完整方案的顺序、预算和失败都可影响最终结果。
- 评分不包含从当前机器人到起点的接近、固定起终姿态、时间或土壤压实。接近仍是原直达单点流程，通行性需单独确认。

## 3. Fields2Cover原生曲线

`turn_library.py`中的`NativeTurns`直接调用选定的Fields2Cover生成器，关闭其粗精度缓存，使用局部坐标生成后转回同一map基准。原半径倍数枚举、U/Ω分类和专门鱼尾候选已按用户最新要求删除。

| 原生形式 | 生成器 | 执行能力 |
| --- | --- | --- |
| Dubins | `PP_DubinsCurves` | 前进 |
| Dubins CC | `PP_DubinsCurvesCC` | 前进，连续曲率 |
| Reeds–Shepp | `PP_ReedsSheppCurves` | 倒车段需明确允许 |
| Reeds–Shepp HC | `PP_ReedsSheppCurvesHC` | 同向段内平滑，倒车段需明确允许 |

每条连接只调用一次选定的生成器，不会自动遍历四种算法。报告最多展示24段连接，JSON含降采样几何和方向，执行路径保存完整采样。原地旋转仍是独立控制动作，不用零半径替代。

新任务最小行进转弯半径默认1 m，已有任务数值不改写。允许倒车时跟踪器按方向分段执行，在换向点停车/航向对齐，详见[原生曲线与倒车跟踪](Fields2Cover原生曲线与倒车跟踪.md)。净空仍是车宽半径圆盘模型，不能代替真实长车体/机具扫掠标定；现有前方180°雷达不保护后方。

## 4. 目标和能耗代理

整田面积`A`=地块扣除禁入区、包含地头。使用与报告和地图完全相同的圆盘足迹网格评价器。先执行净空和前进能力检查，再按以下代价比较；覆盖率不设门槛，也不新增覆盖率惩罚项：

```text
J = wO × (O / 10个百分点)
  + wL × (L / (A / 作业幅宽))
  + wE × (E / ((A / 作业幅宽) × c_forward))
```

`O`为经过至少两次的面积/A的百分数，`L`为完整参考路径长度，`E`为相对能源成本。权重默认`wO=0.35, wL=0.45, wE=0.20`并自动归一化。这些数值是当前工程初值，不是论文给出的通用权重，后续需做敏感性分析。长度与能源代理相关，不能称完全独立目标。

每个非零长度采样段：

```text
κ = abs(wrap(ψ_next − ψ)) / ds
dE = c_direction × [1 + (turn_multiplier − 1) × (κ × R_min)²] × ds
E += switch_count × switch_cost
```

初值：前进直线1单位/m；参考曲率转弯倍率1.5；倒车1.3单位/m；每次换向0.5单位。同一次比较使用同一任务`R_min`参考。未测电流、电压积分或履带滑移，结果不是Wh或真实能耗；倒车成本仅在实际生成的反向路径段存在时计入。

搜索网格至少0.1m；在保留的可执行候选中直接选择该网格评分最低者，再以任务评价网格（默认0.05m，超预算会明确加粗）计算覆盖、重复覆盖等最终指标。细网格覆盖率不会导致拒绝候选或改选其他路径。界面区分搜索指标和最终指标，不对全部方案重新进行细网格评分，不声称全局最优或Pareto最优。

因此，较短或重叠较少的路径可能以更低覆盖率被选中；选中结果不代表整田作业完成，漏覆盖区域仍如实显示、归档。

## 5. 接口、保存位置和代码

| 接口 | 用途 |
| --- | --- |
| `POST /api/missions/{id}/optimize` | 保存后的任务发起优化，创建独立执行记录 |
| `/planning/optimize`，`std_srvs/srv/Trigger` | 覆盖适配器后台进程计算 |
| `/planning/status` | 规划状态、失败原因和目录 |
| `GET /api/runs/{id}/optimization` | 本轮完整候选报告，只读 |
| `/planning/cancel` | 原取消接口同时适用优化 |

所有运动仍经现有安全模块；优化器没有速度发布器。计算在独立低优先级进程执行，不在安全或Web状态回调内运行。

```text
data/experiments/<本轮>/
  config/mission.json                 原始任务及优化参数快照
  paths/coverage_*.json               已校验路径、车体航向、逐点方向、选中参数和元数据
  paths/optimization.json             候选、评分、拒绝原因、模型、预算、坐标、路径和代码指纹
  analysis/coverage_quality_plan.json  规划质量，包含实际选定的地头宽度
  analysis/coverage_quality_report.md  任务结束后的质量及优化摘要
  analysis/coverage_quality.json      数值指标和优化摘要
```

无可行方案时保存FAILED优化报告，不保存可执行coverage路径；覆盖率低本身不会造成FAILED。新优化报告包含`coverage_constraint_enabled:false`，不再输出最低覆盖率或候选“达标”标签。取消或异常退出不能保证已经产生完整候选报告，应以本轮规划状态为准。归档ZIP包含优化JSON。历史任务不回填。

- 算法：`agri_robot_ws/src/agri_path_planning/agri_path_planning/{optimizer,turn_library,planning_options}.py`。
- 共用评价器：同包`coverage_geometry.py`；后端同名模块兼容引用这一实现。
- ROS调度：同包`node.py`；后端：`workspace.py`、`missions.py`、`optimization_results.py`。
- 网页：`TaskEditor.vue`、`OptimizationResults.vue`、`taskParameters.ts`。
