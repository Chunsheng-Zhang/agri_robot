# 四种运行模式与切换

2026-11-13。系统运行模式统一为以下四种。运行模式、运动控制权、任务执行状态分别显示，不再混用。

| 运行模式 | 内部名称 | 正常控制来源 | 用途 |
| --- | --- | --- | --- |
| 基础待命 | `base` | 手柄 `manual`、Web 遥控 `web`，需明确取得权限 | 人工驾驶、设备检查、手柄示教采样 |
| 多点导航 | `waypoint` | `waypoint` | 几何位置/航向控制，顺序到达目标点 |
| 全覆盖规划与跟踪 | `coverage` | `tracking` | 覆盖规划及独立 Pure Pursuit 执行；规划本身不获得运动权限 |
| 路径跟随 | `following` | `following` | 加载示教路径，使用独立 Pure Pursuit 实例跟随 |

手柄原有的明确人工接管仍可从任意模式发起；例如，运行模式仍是“路径跟随”，但人工接管后控制权显示“手柄遥控”，原自主任务结束，不会在松手后自动恢复。Web 遥控只允许在基础待命模式申请权限。任何时候 safety 只授予一个控制源，最终仍仅由 safety 发布 `/cmd_vel`。

软件急停、障碍停车、故障、暂停、航向对齐、示教录制均不是新增运行模式。示教录制属于基础待命模式下的功能，完成录制不自动转成自主跟随。

## 网页操作

系统总览、作业监控、多点导航、全覆盖规划与跟踪、路径跟随页面都使用统一的四按钮模式选择栏。点击侧边栏目只切换页面，不改变车辆模式。

- 点击另一个运行模式时，现有运动会停车、旧控制权撤销，新模式保持待命。存在运行/暂停/申请中的任务、规划或录制时会先提示确认。
- 确认框打开期间按钮锁定；取消、离开页面或安全状态过期，不能由迟到确认继续切换。
- 重复选择当前模式不停车、不撤权、不递增模式版本，也不重新开始任务。停车请用取消任务、释放遥控或急停，不依赖重复点击模式按钮。
- 示教采样开始时保存模式版本；切换出去后迅速切回基础待命也会终止旧录制，保留原始记录并标记失败，不能跨模式拼接成可执行路径。已经结束采样的后台处理可以继续。
- 各栏目执行按钮仍绑定自己的任务类型。例如在多点导航栏目选择路径跟随模式，不能误启动多点任务，须进入对应栏目加载并明确开始。
- 总览和安全卡片分别显示“运行模式”与“当前控制权”。实时任务列表包括多点、覆盖跟踪、示教跟随及覆盖规划，运行记录也标注所属模式。
- 作业监控按当前模式选择参考路径和实际轨迹。模式切换后立即清除旧画布数据，上一轮迟到响应不能覆盖新模式；基础待命不显示上一任务的参考线。

急停解除仍只解除锁定，不开始或恢复任何任务。雷达与定位保护、手柄断联保护和速度上限沿用现有规则。

## ROS 与后端口径

模式与自主控制源映射由 `agri_base/modes.py` 集中定义；安全节点、任务公共逻辑、统一 launch、后端模式网关和执行状态路由共用该定义。前端的 `api/workspace.ts` 集中维护四个按钮及名称。

```bash
ros2 service call /system/mode/base std_srvs/srv/Trigger '{}'
ros2 service call /system/mode/waypoint std_srvs/srv/Trigger '{}'
ros2 service call /system/mode/coverage std_srvs/srv/Trigger '{}'
ros2 service call /system/mode/following std_srvs/srv/Trigger '{}'
```

以上命令会实际切换模式，只在明确需要停车并切换时使用。统一启动的 `mode:=...` 只设置初始模式，默认 `base`；初始急停锁定和任务待命不变，不因选择初始自主模式而行驶。

`/safety/status.mode` 和 `/api/devices` 的 `safety.mode` 是当前运行模式，`owner` 是实际控制源，`mode_revision` 用于拒绝旧控制请求。`/api/robot/status.work_mode` 采用同一模式口径；兼容字段 `mode` 仍表示旧的 offline/running/standby 运动概况，`control_mode` 仍是控制源，不应把它们当作四种运行模式。

后端 `/api/system/mode` 接受四个内部名称。同模式重复请求保持幂等；切换不自动取得新控制权。`/api/tasks/following/pause|resume|cancel` 支持通用任务控制，但跟随开始仍必须走 `/api/following/start`，校验路径、原点、起点距离和本轮记录器，不能绕过完整检查。

作业监控使用 `/api/following/path/reference` 和 `/api/following/path/tracked` 获取跟随几何；原覆盖参考接口保持独立。普通实际轨迹接口可用 `source=tracking|waypoint` 限定来源，避免把另一控制器的缓存轨迹当作本轮轨迹。总览点数也按当前模式选取，基础待命清零。

## 验证与生效

日志目录：`.diagnostics/four_modes/`。本次验证使用 localhost 隔离 ROS Domain 229，无真实设备驱动或实车运动。

- `python.log`：372 项 Python/FastAPI 回归通过，22 项隔离/环境用例跳过。
- `ros.log`：5 项隔离 ROS 用例通过，覆盖全部 12 种跨模式切换、重复选择、旧请求/旧释放拒绝、急停保持锁定、参考路径冲突及完整示教跟随闭环。
- `web-mode-final2.log`：7 项实际 Vue 脚本用例通过，包括四按钮、确认串行、迟到确认、过期状态和监控地图来源切换。
- `web-tests-complete.log`：124 项前端回归通过，包含本机模拟 HTTP 代理检查。
- `ros-build-complete.log`、`web-build-complete.log`：ROS 包构建、前端类型检查与生产构建通过。

当前真实服务没有自动重启。停车并结束任务后，按原设备开关重启核心与后端、刷新网页，新口径才完整生效。无需修改现场原点、速度或手柄参数。仍需实车验证切换时的物理停车响应。
