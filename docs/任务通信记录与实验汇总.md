## 跟踪精度口径

报告列出本轮任务参数、结束状态/原因、横向与航向误差、分区指标、终点误差、进度、速度、角速度指令上限占比、暂停与采集完整性。

- 横向/航向误差：带符号均值、MAE、RMSE、总体标准差、绝对误差中位数、P95、P99、最大值。横向误差报告表使用厘米，航向使用度；JSON原有米/弧度字段保留。
- 横向误差在5/10/20厘米内的样本比例。这些是描述性分档，不是自动设定的合格标准。
- 分别统计全部正式跟踪、去掉正式跟踪最初5秒、去起步后的直线核心区、去起步后的转弯/衔接区。
- 直线核心区要求参考进度前后1米内的顶点曲率绝对值均小于0.15 rad/m，且距整条路径两端大于1米。顶点曲率为相邻线段的转角（wrap到±pi）除以两段平均长度。分类依赖参考路径采样密度，不是规划器原生行类型；无样本时留空，不输出0误差。
- 接近、航向对齐单独统计，不混入正式跟踪。恢复后的正式跟踪样本保留，不为美化结果任意删除。对齐文件跨多次恢复，其总记录跨度及位置连线不能当作原地旋转的时间或行驶距离。
- 进度为最后路径进度÷参考路径长度，不是地块实际作业覆盖率；失败任务的指标只代表已经记录的路段。
- 暂停次数和各状态时长只使用匹配本轮`run_directory`的任务状态，按相邻接收时刻估算；保留最大状态间隔和异常时间。缺少状态不能臆定暂停次数为0。
- MGX23实测水平速度按原始NED输出计算，不由位置差分补造。速度比较只在正式跟踪时间范围附近进行，以最近的、不超过0.25秒的控制器源时间匹配，比较两者水平速度模长。它没有补偿底盘惯性/滤波响应，不能直接推断纯通信延迟或限速位置。
- 角速度接近上限比例，统计正式跟踪附近控制器样本中`|w| >= 0.99 × 任务max_angular`的比例；是指令样本比例，不是已独立测量的执行器饱和时间。

所有精度指标按记录样本统计，未按时间/距离重新加权；缺失、暂停和采样密度会影响权重。同一MGX23定位用于控制和评价，不是独立真值精度。没有为美化图形修改原点、平移或旋转轨迹。程序不自动给出“整轮合格”的总分。

## 通信统计实际测到了什么

| 指标 | 定义与边界 |
| --- | --- |
| 原始块序号缺口率 | 每个驱动session的首末序号范围为分母，缺少的唯一序号为分子。序号在驱动收到字节后生成，不是IP包序号；窗口外损失未知 |
| 同源消息未匹配率 | 位置观察窗口前后各去1秒作为参考，按完全相同Header在姿态/速度/odom中寻找；短窗口不足则未测。四路共同缺失不能由此识别 |
| NAVI节奏 | 从原始字节检查完整NAVI的校验、设备时间重复/跳变，按10Hz估算时间槽缺口；可能由设备停发、链路或记录缺失造成，不定位原因 |
| ROS消息年龄 | 本机源时间戳至记录器接收的年龄，均值/P50/P95/P99/最大值；不包括MGX23全部内部解算时间 |
| 接收间隔 | 单调接收时间的间隔和实收频率，暂停/空闲不主动发指令时不能直接算消息丢失 |
| 后端HTTP耗时 | 请求进入ASGI到应用处理和发送完成的耗时，包括本机调度/等待；不等于浏览器完整RTT或浏览器超时率 |
| 记录器丢弃/错误 | 有界队列和写盘/解析报告；与原始块缺口可能重叠，不把两种比例相加 |

ROS源时间缺失时，延迟显示未测；负年龄单独计数并从分布排除。雷达Header通常对应首束采集，年龄包含一圈扫描成帧时间。100ms是统一诊断参考线，不是安全停车阈值或行业强制验收线。

NAVI时间为UTC `HHMMSS.ss`，先转为一天内秒数再算间隔，处理跨分钟和跨午夜。跨原始序号缺口不拼接残帧；其他协议报文不会直接当作损坏的NAVI。无完整帧或间隔不足时不臆造“零源样本缺失”。

后端只旁路观察实际发生的GET `/api/robot/status`、`/api/devices`、`/api/workspace`、`/api/camera/stream-info`，提供失败/未完成次数和超过2000ms的比例，2秒参考现有GET期限。请求开始时绑定轮次，慢请求不会记入下一轮；轮次停止接受数据之后才完成的请求无法写入该轮，所以不能声称覆盖所有浏览器尝试。未观察到请求时明确报告未测。

以下指标明确标为未测：底层IP丢包率、操作电脑到Jetson的浏览器完整往返延迟、车体执行延迟。它们需要额外的两端或执行响应测量点；不能用现有序号、后端耗时或速度滞后冒充。

## 对运行的影响与生效

新增两张图自动嵌入 `analysis/report.md` 和 `README.md`，跟原有四图一样只在任务关闭后的独立分析进程中生成。缺失率按10秒窗口统计；原始序号缺口与对应序号跨度统一归到后一个已接收片段所在窗口，因为缺失片段的确切发送时间未知。会话重启不算缺口，空窗口留空；各窗口分子/分母可在绘图JSON中复核。同源匹配在整轮范围查找Header后再按位置参考样本接收时间分窗，避免把跨窗口迟到误判成缺失。

延迟图按1秒窗口画P95实线和最大值点线，另附整轮均值、P95、P99、最大值和超过参考线比例的表格。无源时间、负消息年龄和无数据窗口不画成0延迟。HTTP和丢弃事件的单调时间，通过最近且不超过1秒的ROS接收锚点换算到跟踪图时基，不假设Unix墙钟与ROS仿真时钟相等；找不到锚点的数量单独报告。

时间零点与原跟踪图相同，负时间通常为接近/对齐阶段。底色用匹配本轮目录的任务状态标注Approach、Align、Track、Pause；状态空档超过1秒不连续着色，不靠轨迹空档猜暂停。没有正式跟踪或状态时，使用实际可用的首样本时基并注明缺少阶段信息。

记录器新增最多1000个队列丢弃事件的单调时间点，超出部分保留总计数和截断数量，不无限占用内存。队列丢弃与序号缺口可能描述同一缺失，图上分开呈现、不相加。无计数或无时间点时标注未测/时间不可用，不伪造事件时间。

ROS回调继续只向有界队列放数据，后台线程写CSV，结束后独立子进程统计/绘图。复用现有遥测，额外只订阅`/scan`和`/joy`的消息头，不保存雷达点阵或相机原图。不会新增ping、抓包、状态轮询、相机预览或运动指令。

HTTP旁路不记录请求体、响应体、查询参数、地图Key或认证信息；诊断失败不改变接口返回或控制行为。通信文件创建失败仍在显式开始服务调用前拒绝本轮启动，避免无记录地开始任务。

本次为后端Python采集和分析更新，无需构建MGX23或更改控制器参数。后端加载新代码后，后续新开始的任务自动生效；不能在任务运行中重启后端。原始数据、任务配置、历史运行目录和归档文件均不回写。
