# Fields2Cover原生TSP接入与验证

日期：2026-11-14。本文记录当前“一键优化规划”的实现和软件验证。未进行实车运动或真实机具作业验证，没有升级系统、Fields2Cover或厂商驱动。开发验证阶段未重启现有核心与后端；同日后续运行服务恢复见下文。

## 当前流程

用户明确允许跨分区访问作业行，不要求每个分区连续完成。现已删除智能规划中的自定义分区块2-opt和四状态DP，复用本机既有Fields2Cover 2.0：

```text
同一固定原点下的边界/禁入区
  → 完整旋转圆包络计算安全内缩
  → 按候选方向旋转到局部扫描坐标并稳定数值
  → 原生Boustrophedon分解（必要时原生Trapezoidal分解）
  → 检查每区扫描单调、分区并集完整
  → SG_BruteForce生成SwathsByCells
  → 原生RP_RoutePlannerBase.genRoute / OR-Tools TSP
  → 读取全部作业行及完整Route连接
  → 重采样并插入停车原地转向标记
  → 完整净空检查、统一覆盖评价、固定权重择优
```

TSP在全部条带间选择访问顺序和朝向，可离开一个分区后再进入。`row_orientation=REVERSED`只表示相对条带原始点序反向遍历，车身航向仍按前进切线生成，不代表允许车辆倒车。完整Route连接不能改成跨作业区的直线，也不能只保留条带再由项目自行乱序拼接。

保留原来的完整粗细角度集合：PCA方向及其垂直方向、0–165°的15°网格，随后围绕当前较优方向比较±5°、±2°、±0.5°。仍按以下外层代价评价完整方案，无最低覆盖率约束：

```text
J = 0.5*(1-C/100) + 0.3*O/100 + 0.2*L/(L+A/W)
```

C/O为整田扣除禁入区、包含地头的覆盖率/至少两次覆盖率；所有候选共用实际评价网格和有效机具幅宽。L含作业行、全部连接；有人工入口时再计入口参考距离，入口连接不计覆盖。

**原生TSP内部优化路由代价，外层再比较覆盖/重复/长度，并非对所有访问排列直接求三目标联合最优。** 每次原生调用沿用本地库1秒启发式设置，`search_for_optimum=False`；完整完成角度搜索不等于枚举全部TSP排列或证明全局最优。没有恢复45秒整轮截断或候选数量上限。进度、人工取消及外层120秒异常保护保留；取消/超时不发布部分较优路径。

## 人工入口与开放路径

无入口：每方向生成一条自由开放路线。

有入口：每方向最多比较四种完整方案：

| variant | 方案 |
| --- | --- |
| 0 | 原生自由开放路线原起端 |
| 1 | 同一路线从另一端开始，全部连接反向保留 |
| 2 | 原生入口引导闭环去掉入口接近、返程后的原起端 |
| 3 | 上述入口引导开放路线的另一端 |

本地2.x只暴露相同起终点的`setStartAndEndPoint`，所以入口引导闭环仅作为另一个原生排序种子。只去掉首尾入口连接，全部作业行及作业行间连接原样保留，不称精确的固定入口开放TSP最优解。省略的首尾连接保存在审计元数据，不下发执行。入口锚点与条带端点或中点重合时，拒绝这个种子以规避原生图的新增节点假设；保留自由路线比较，不移动用户入口。

**入口仍与执行接近解耦。** 明确开始覆盖后，车辆按原规则直接单点接近规划首点，再航向对齐、Pure Pursuit；不先经过入口，不执行原生闭环返程。接近段未因此获得静态绕障能力。

## 稳定性和安全校验

- 每方向只在工作进程中旋转、按1微米精度处理几何，逆变换回统一map。原始GNSS、边界、原点和历史路径不回写。已修复单孔投影浮点几何在0°/90°下分解不足的问题；精确/投影往返输入的0°/45°/90°均纳入回归。
- 每区必须扫描单调、无孔，分区并集保留完整安全工作区。原生BCD不足时尝试原生梯形分解，两者都不足则拒绝该方向。安全内缩后不连通的工作区明确失败，不静默遗漏分区。
- 每条作业行有全局唯一编号；原生输出必须恰好访问全部作业行一次，端点与输入一致，连接无空档。合理重走连接仍可出现，不能将“没有越界”扩大为“绝无交叉或压实”。
- 安全内缩保留保守mitre折角；平移和转向均检查完整圆包络。默认长0.45m、宽0.2m、余量0.05m，半径约0.296221m，地头再加0.0001m数值裕量。上述尺寸尚非实车标定。
- 原生Graph2D保存全点对通道路径，存在内存增长风险。端点加边界角点的规模估计超过768时拒绝该方向；另保留1500条作业行及既有采样/网格资源保护。这些是单次几何规模限制，不是候选数量上限，不会返回残缺路径。
- 同XY不同航向的Pose、停车等待/对齐、速度仲裁、定位异常、急停、暂停继续、取消均复用现有链路。旧曲线、回形、手工排序及其倒车权限保持原规则。

## 请求绑定与保存加载

联调发现并修复两个兼容问题：

1. 后端还用`POINT_TURN_ANGLE`标记新规划，导致加载后显示旧策略。现统一标记`POINT_TURN_NATIVE_TSP`，旧、新点转路径都必须校验姿态/停车标记指纹，不能因默认不倒车跳过。
2. 连续规划时，上一轮迟到的终态可能在下一轮请求后到达，单用接收时间会误判本轮已失败。规划与加载配置传本轮run id，节点在接收请求时快照为`active_request_id`，发布到`/planning/status.request_id`；后端忽略不匹配状态。不是在每次发布时读取可被下一轮改写的参数。

新路径`policy_version=4`，优化报告`schema_version=2`、`policy=POINT_TURN_NATIVE_TSP`。最佳路径保留`swath_visits`、`native_route_connections`、分区访问序列/回入数、作业行/连接长度及入口省略连接；候选表只保存评分和摘要，避免重复存储全部几何。原生TSP设置及实现文件SHA256写入本轮报告。

保存/加载仍核对任务版本、固定原点、入口、车辆包络和姿态指纹。加载不会重新排序或开始运动；已保存历史路径和实验数据不迁移、不重写。获取新策略结果必须重新规划，明确保存才加入左侧复用列表。

单/双禁入区路径允许回入分区1/2次，证明确实没有保留分区连续约束。不是所有指标或地块都改善：凹地块B长度、重复率上升；方向选择和路由均为有限搜索/启发式，不能据原生接入声称所有情况更优。单孔转向数也略增。覆盖率数字是几何预测，不是实测作业质量。

## 复用依据

- [Fields2Cover官方分解教程](https://fields2cover.github.io/source/tutorials/decomposition.html)：原生往复/梯形分解与带孔地块处理。
- [Fields2Cover官方路由教程](https://fields2cover.github.io/source/tutorials/route_planning.html)：保留`SwathsByCells`，由原生路由生成作业行顺序和连接。
- [Mier等，2023，IEEE Robotics and Automation Letters](https://doi.org/10.1109/LRA.2023.3248439)：复用Fields2Cover模块化覆盖规划组件。这里是项目适配，不声称完整复现任一论文最优性结果。
- [Höffmann等，2024，Journal of Field Robotics](https://doi.org/10.1002/rob.22286)：区分几何分解、方向、访问顺序与可行连接。当前评分和几何模型仍需实车机具数据验证。

本地2.x与v3源码差异及固定提交见[Fields2Cover源码分析](2026-11-14_Fields2Cover_v3源码与复杂地块处理分析.md)。本次没有迁移v3，也没有把上游曲线模型直接套用于履带原地转向。
