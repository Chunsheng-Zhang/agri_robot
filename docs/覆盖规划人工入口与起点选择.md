# 覆盖规划人工入口与起点选择

2026-11-13。已同时接入普通“生成覆盖路径”和“一键优化规划”。入口由人工设置，不默认使用车辆当前位置。设置入口、保存任务、生成或加载路径都不会开始运动。

## 网页操作

在“全覆盖规划与跟踪”任务编辑区的 **作业入口设置** 中选择：

- **输入经纬度**：输入 WGS84 十进制度的经度和纬度，不使用度分秒或 GCJ/BD 偏移坐标。
- **地图选择入口**：点击“在地图上选入口”，在下方米制覆盖地图点击位置；也可拖动紫色入口旗标调整。选点会自动反算经纬度，缩放和拖动地图不会改变坐标基准。

两种方式设置同一个固定参考点，经纬度和图上标记联动。入口与边界、参考路径、车辆位置都使用项目现有固定 UTM 原点，入口不改变 map 原点。

操作流程：**设置入口 → 保存任务 → 生成覆盖路径／一键优化规划 → 查看入口与实际起点 → 保存规划路径 → 明确开始任务**。

修改入口使任务草稿变为未保存，旧规划不再允许直接开始。保存后任务版本增加，须重新规划。入口随任务 JSON 导入导出；经纬度填写不完整、坐标越界或位于禁入区时会明确拒绝。清除入口并保存后沿用原起点规则，保留无入口任务的兼容行为，历史文件不回写。

## 地图上的三个位置

| 标记/线 | 语义 |
| --- | --- |
| 紫色旗标“入口” | 人工指定的入口参考位置 |
| 绿色圆点“起点” | 正式覆盖路径首点，不一定与入口重合 |
| 红色圆点“终点” | 正式覆盖路径末点 |
| 紫色虚线 | 用于规划起点比较的参考连接，不是车辆执行接近路线 |
| 灰色点状线及“内缩安全点” | 入口不在安全中心线区域时的投影关系，仅为未验证通道示意 |

入口可以设在田边或田外。系统在地块内缩安全区域中确定最近的入口锚点，再连接到覆盖起点。灰线仅为规划示意，入口参考连接不下发给控制器；入口在禁入区内或其边界上直接拒绝。车辆执行接近仍使用下述原有单点导航。

地图显示的 **入口参考距离** 为“入口到安全锚点的示意距离＋锚点到覆盖起点的已知区域连接长度”，并单独显示已验证连接长度和说明。它不代表车辆实时到起点的距离，也不是已测行驶里程。

## 两种规划如何选起点

普通规划继续由 OpenNav Coverage 生成地头和作业行，随后在独立工作进程中使用 Fields2Cover 原生牛耕、蛇形或分组螺旋排序的四种起步方式，重新生成所选原生转弯曲线并检查完整路径。原生螺旋分组大小保持 OpenNav 默认4。可行方案中先比较入口距离，相同时比较正式路径长度，不裁掉前半段作业行、不把路径中间最近点直接作为起点。四种原生曲线与明确倒车权限继续生效。

回形保持从最内侧向外连续展开，比较不同可行起缝方向；不把最外圈改成起点，不倒转层序，也不退回逐圈闭合连接。

智能规划固定原地转向、人工幅宽、最小安全地头及完整粗细角度搜索；2026-11-14已改用Fields2Cover原生分解、条带级TSP和Route连接，允许跨分区访问。设置入口后，每方向最多比较四种：原生自由开放路线的两个起端（variant 0/1），以及原生入口引导种子去掉入口接近/返程后的两个起端（variant 2/3）。本地2.x入口接口为闭环，该种子只辅助访问排序，不声称精确固定入口开放TSP最优；作业行间连接完整保留，入口首尾连接不执行。未设置入口时每方向评价一条自由路线。原手工规划的四种原生排序不受此改变影响。权重仍为覆盖率0.5、重复覆盖0.3、长度0.2：

```
L = 正式作业行及换行连接长度 + 入口参考距离
score = 0.5*(1-C/100) + 0.3*O/100 + 0.2*L/(L+A/W)
```

所有候选用同一评价网格，覆盖率和重复率只评价正式参考路径，不把入口连接当作已经作业。报告分别保存 `working_length_m`、`entry_length_m` 与合计 `length_m`；田外示意距离明确保留未验证属性。未设置入口时保留既有评分口径。

智能规划仍完整执行既定搜索，不增加候选上限或主动时间预算；人工取消和既有外层 `planning_timeout` 保护继续生效，取消/超时不发布部分结果。设置入口后候选计算量增加，有限搜索不保证全局最优。

## 开始执行与接近记录

**人工入口与实际接近执行完全独立。** 不论是否设置入口，点击“前往起点并开始覆盖”后，沿用原有流程：

1. 获取车辆实时位置，目标始终为正式参考路径第一个点。
2. 距离大于 `start_tolerance`（默认0.8 m）时进入 APPROACHING，由原有 `WaypointController` 单点导航到覆盖起点。
3. 接近完成后进入 ALIGNING，对齐首段航向，再进入 TRACKING，使用 Pure Pursuit 正式跟踪。
4. 已在阈值以内时先对齐再跟踪。暂停/继续、定位异常、雷达停车、急停及控制权规则保持原样。

不会先前往人工入口或内缩锚点，不读取入口参考连接作为执行路线，也不因车辆位于地块外而额外拒绝开始。单点接近仍保持coverage模式及同一次tracking控制权，不启动另一份多点任务、不切换系统模式。启动程序本身不会自动行驶，仍须明确开始任务。

入口参考连接只用于规划比较及长度目标，`entry_length_m` 不代表车辆实际单点接近行驶长度。实际接近仍为原有直达导航，不新增道路规划或绕障能力；通道确认要求沿用原项目约定。

接近期间正式覆盖进度保持0；接近、航向对齐和正式跟踪继续分别写入 `approach_*.csv/.json`、`alignment_*.csv/.json`、`track_*.csv/.json`，不把接近误差混入正式覆盖精度或覆盖率。

## 保存、校验与代码

- `data/web/missions/<任务ID>.json`：`entry.latitude/longitude/source`，以及预览中的固定原点 map 坐标。
- `data/experiments/<运行ID>/config/mission.json`：本轮不可混用的任务/入口快照。
- `paths/coverage_*.json` 的 `planning.entry`：入口、内缩锚点、正式起点、连接几何、距离及验证属性；普通方案另含四候选统计，智能报告保留全部候选评分。
- 接近执行不生成或读取 `entry_approach.json`，也没有 `approach_path_file` 参数；旧文件仅作为历史产物保留，不参与当前控制。

保存/加载同时核对任务版本、入口、原点、参考路径、包络和入口连接。加载保存路径保留原起点，不因车辆位置变化而悄悄重排。新的路径和执行目录分别保存，来源记录不覆盖。

主要实现为 `agri_path_planning/entry.py`、`entry_planner.py`、`optimizer.py`、`node.py`；后端为 `missions.py`、`workspace.py`、`saved_plans.py`；前端为 `TaskEditor.vue`、`FieldMap.vue`。ROS 规划参数 `entry_config`（WGS84 JSON，`null`清除）仅由规划模块使用，跟踪器不接收入口参数。网页地图反算接口为只读计算 POST `/api/coordinates/map-to-wgs84`，请求包含 x/y 和固定投影身份，原点不符时拒绝。

本次没有启动车辆或重启实际服务。软件验证日志在 `.diagnostics/field_entry/`；停车并结束任务后重启更新后的核心与后端、刷新网页使用。实际GNSS误差、物理停车及机具开关仍需实车验证。
