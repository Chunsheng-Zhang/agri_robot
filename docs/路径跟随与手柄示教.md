# 路径跟随与手柄示教

本功能用于先用手柄沿田间道路行驶一次，再自主重复跟随。入口为系统导航 → **路径跟随**（`/following`），在“全覆盖规划与跟踪”下面。它不调用覆盖规划器，不修改手柄按键，也不依赖地块边界。

## 使用流程

1. 使用现有一键启动入口启动系统，打开 Web 的“路径跟随”。MGX23 与手柄须已连接，定位有效。进入页面不切换模式、不取得运动权限。
2. 明确选择“基础待命”，输入名称，按需设置“允许倒车”。默认只支持前进示教；录制使用已有后台处理缺省值。
3. 点击“开始录制”，用原有手柄控制权及摇杆沿道路行驶；不要横向平移。录制只旁听定位，不向底盘发速度。
4. **先用手柄停车**，再点“结束录制并保存”。该按钮停止采样，不代替手柄停车。处理成功后，路径进入左侧列表。取消/失败保留原始记录，但不产生可执行路径。
5. 在左侧按名称查询并选择路径，预览参考线、绿色起点和红色终点。检查平滑后路线及转角是否符合道路实际通行条件。
6. 用手柄将车移到示教起点附近并停车，释放手柄控制权，明确切换“路径跟随”模式，点击“加载此路径”。路径加载与开始分开，加载不会行驶。
7. 默认起点允许距离 0.3 m（可设 0.05–2 m，2026-11-28按用户要求提高上限），超过门槛会拒绝开始，**不会从远处自动直线接近起点**。等待参考路径确认后，点击“开始路径跟随”。先原地对齐，再按采样顺序执行。起点距离是距首点的直线距离；跟踪时仍独立检查最大路径偏离，默认0.5 m，提高起点距离不会同时提高偏离阈值。
8. 页面实时显示参考路径、实际轨迹、当前位置、带符号横向误差、航向误差、进度和状态。可暂停、继续、取消。继续时重新对齐；急停或故障后不自动恢复。顶部急停和手柄 6 键沿用原有最高优先级。

同一路径可以重复执行。每次从开头开始，生成新的执行目录，不覆盖示教记录或前一轮数据。这里的“允许倒车”是保留并复现示教中的倒车段，不是把整条路线反向执行。沿用现有前方 180° 雷达策略，倒车没有后向雷达保护。

## 从文件导入道路轨迹

也可以不录制，直接在本页“录制或导入路径”中填写名称和“允许倒车”，然后点击 **导入文件**。2026-11-27按用户要求取消文件导入重采样、平滑及按最小距离删点，保留原始点数、点序、坐标及文件提供的航向；页面移除重采样和平滑输入项。后端可在没有连接车辆时按配置原点导入；录制/处理中或跟随任务未结束时禁止导入。成功后自动预览并加入左侧“已保存路径”，标注“文件导入”。导入不切换模式、不替换已加载参考、不发布 ROS 路径或速度；仍需明确“加载此路径”后再“开始路径跟随”，起点附近启动、航向对齐、暂停/继续、取消和安全条件与录制路径相同。

支持 UTF-8 文件，大小不超过 **2 MiB**，输入 **3–20000 点**，有效长度至少 **0.5 m**，导入后点数与输入一致。按文件顺序行驶，不自动排序或闭合。CSV/JSON 的经纬度为 WGS84；不要使用 GCJ-02/BD-09 坐标。GeoJSON 必须是道路折线 `LineString`，地块边界 `Polygon` 和 `FeatureCollection` 不能当作道路导入。

经纬度 CSV（首行为字段名，可用 Excel 另存为 UTF-8 CSV）：

```csv
longitude,latitude
117.021433066391,36.6468527633281
117.021444300000,36.6468527633281
117.021455500000,36.6468527633281
```

经纬度 JSON（`points` 或 `waypoints` 数组）：

```json
{"points":[
  {"longitude":117.021433066391,"latitude":36.6468527633281},
  {"longitude":117.021444300000,"latitude":36.6468527633281},
  {"longitude":117.021455500000,"latitude":36.6468527633281}
]}
```

GeoJSON（可直接使用 `LineString`，也可像下面使用单个 `Feature`）：

```json
{"type":"Feature","properties":{},"geometry":{"type":"LineString","coordinates":[
  [117.021433066391,36.6468527633281],
  [117.021444300000,36.6468527633281],
  [117.021455500000,36.6468527633281]
]}}
```

本地平面坐标只支持 JSON，必须写明 `frame_id: "map"` 和与系统完全相同的 `projection`；不接受没有原点的裸 `x/y`，不自动归零。示例：

```json
{"frame_id":"map","projection":{"epsg":32650,"latitude":36.6468527633281,"longitude":117.021433066391},
 "points":[{"x":20,"y":10},{"x":21,"y":10},{"x":22,"y":10}]}
```

CSV 和点对象 JSON 可以为**每一个点**提供 `yaw`，必须全部提供或全部省略。它表示车体在 ROS map 中的航向（东向 0、逆时针为正、弧度、范围 [-π,π]），**不能直接填写 MGX23 北向顺时针航向**。省略时按坐标点序推导前进行驶航向；即使勾选允许倒车，也不会凭点序猜测真实倒车。要描述倒车段，需提供车体航向并勾选“允许倒车”；不匹配的横向位移会拒绝导入。GeoJSON 不使用高程作为航向。

导入只做格式、投影、有限值、长度、方向、倒车权限及显式停车转向标记检查；经纬度按系统固定原点转换成map，不移动或重排点，不重新生成已有yaw。相邻行驶段夹角大于40°且行驶方向未换向时，需在文件中用同XY、不同入/出yaw的相邻点显式标记停车转向；缺少标记会拒绝导入，不再自动插入转向姿态。已有重复点保留在文件中，跟踪器仍沿用原有重复点与换向解析。**没有真实采样时间，因此不做速度跳点、时间回退或定位空档检查，不推算实测速度**；即使文件另带时间列，当前坐标导入也不把它作为有效时间序列。请在预览时核对不合理长连接、道路净空和可通行性；文件导入不是道路安全验证。

可直接导入的两份合成测试文件（同一条约 10 m 的弯曲路线，位于固定原点附近，不是实测道路）：

- [CSV 示例](../data/paths/import_examples/following_route.csv)
- [GeoJSON 示例](../data/paths/import_examples/following_route.geojson)

## 定位、轨迹处理与文件

采样来自 `/odom` 的 `base_link` 位姿，它由现有 MGX23 GNSS/INS 转换得到，**不是轮式编码器里程计**。沿用唯一固定 UTM 原点，map 与 odom 重合；不会分别把录制、参考、实际轨迹归零。文件写明投影、原点、单位和来源。

处理保持时间顺序，不按空间最近距离重新排列。步骤为：有限数值检查 → 孤立速度跳点剔除 → 时间连续性/持续跳变检查 → 静止微小位移过滤 → 局部中值及加权平滑 → 按弧长重采样 → 航向/前后方向校验。默认最小保留距离 0.03 m、重采样间距 0.1 m、最大平滑位移 0.03 m、跳变检测速度门槛 1.5 m/s。首尾端点保留，明显急角及换向点保持锚定，必要时生成同 XY 不同航向的显式停车转向标记。

超过 0.5 s 定位空档、时间回退、定位无效、手柄失联、安全锁定、模式/原点变化都会终止录制，不自动拼接后续路段。录制最多 1 小时/20 万样本，处理结果最多 10 万点，超限明确提示分段示教。道路横移、未授权倒车或不可用轨迹会明确拒绝保存为可执行路径。

```
data/taught_paths/<路径ID>/
  metadata.json    名称、状态、原点、处理参数、统计、删除标记
  raw.csv          原始位姿采样 stamp,x,y,yaw；后台约每 0.1 s 刷盘
  path.json        处理后的 map 路径、完整姿态、文件指纹及 ROS 传输指纹
```

名称和文件 ID 分开，重命名不改变路径几何。删除移除库中条目并禁止后续加载，保留原始文件和既有执行档案；使用中的路径不能删除或替换。后端异常退出时，启动后将未完成记录标为故障，不自动继续录制或恢复运动。这些现场数据已加入 Git 忽略规则。

平滑只是对定位轨迹作有限修改，不证明道路宽度、障碍净空或 GNSS 绝对精度。误差评价和控制使用同一 MGX23 定位，没有独立真值。

## 跟随控制与 ROS 接口

复用 `agri_path_tracking/node.py`、`controller.py` 与 `coverage.py` 中的 Pure Pursuit、分段进度、航向对齐、停车换向及记录逻辑，新实例名为 `path_follower`。原覆盖控制器 `path_tracker` 继续使用原接口。

| 接口 | 类型/发布方 | 使用方/说明 |
| --- | --- | --- |
| `/odom` | `nav_msgs/Odometry`，定位节点 | 示教采样和跟随反馈，odom/base_link |
| `/localization/valid` | `std_msgs/Bool`，定位节点 | 录制及自主执行有效性 |
| `/localization/origin` | 持久 `std_msgs/String`，定位节点 | 固定原点核对 |
| `/following/reference_path` | 持久 `nav_msgs/Path`，后端示教库 | 独立跟随参考，map；加载时发布 |
| `/following/tracked_path` | `nav_msgs/Path`，path_follower | 实际轨迹，map；约 2 Hz 和任务结束 |
| `/following/error` | `geometry_msgs/Vector3Stamped`，path_follower | map；x=路径段偏离距离，y=航向误差，z=进度，约 20 Hz；安全校验使用偏离距离 |
| `/following/status` | 持久 `std_msgs/String`，path_follower | 状态/阶段/进度/带符号 lateral_error/路径指纹，约 20 Hz |
| `/control/following/cmd_vel` | `geometry_msgs/TwistStamped`，path_follower | safety 唯一仲裁；base_link，约 20 Hz |
| `/following/start,pause,resume,cancel` | `std_srvs/Trigger` | 开始、暂停、继续、取消；开始异步申请安全控制权 |
| `/system/mode/following` | `std_srvs/Trigger`，safety | 新独立模式；切换后保持待命 |

安全模块只允许对应模式的控制器取得唯一控制权；多点、覆盖、示教跟随不能同时控制底盘。手柄主动接管、急停、定位超时、速度限幅、路径偏离保护和雷达开关继续生效。最终仍只有 safety 发布 `/cmd_vel`。

网页 API 在 `/api/following/` 下：`context`、`record/start|stop|cancel`、`paths/{id}`（查询/重命名/删除）、`paths/{id}/load`、`start`、`task/pause|resume|cancel`。录制由后端工作线程保存和处理，关闭网页不会悄悄停止采样；后端停止则录制中断。路径执行由 ROS 节点负责，网页关闭不等于取消任务。

新节点默认参数在统一 `system.yaml` 和 `config/jetson_system.yaml` 的 `path_follower` 段：速度 0.1 m/s、前视 0.5 m、最大角速度 0.5 rad/s、最大偏离 0.5 m。网页开始时下发本轮参数并归档，不改全局 YAML。跟随节点随统一核心常驻启动，不需要启动覆盖规划器。

## 执行数据与代码位置

每次明确开始跟随后，记录到 `data/experiments/<本轮ID>/`：

- `config/mission.json`：本轮来源示教路径、原点和跟随参数；`paths/following_reference.json`：本轮参考快照。
- `tracks/track_*.csv/.json`：正式跟随轨迹与横向/航向误差；`alignment_*.csv/.json`：航向对齐，分开统计。
- `raw/`、`telemetry/`、`communication/`：沿用现有 MGX23 原始字节、解析数据、各级速度指令、底盘反馈和通信记录；话题缺失明确报告。
- `analysis/`：四图、`trajectory_and_speed.png`、指标 JSON/CSV、中文 `report.md`；这是道路跟踪评价，不生成农田覆盖率报告。

主要代码：`agri_backend/taught_paths.py`（处理/文件库）、`agri_backend/following.py`（录制/ROS桥接/API）、`agri_path_tracking/node.py`（独立跟随实例）、`agri_safety/node.py` 与 `gate.py`（模式/权限/安全）、`agri_web/src/views/FollowingView.vue` 和 `components/FollowingMap.vue`（网页）。
