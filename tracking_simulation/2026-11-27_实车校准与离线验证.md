# X3硬质地面实车校准与离线验证

日期：2026-11-27，Asia/Shanghai。本轮改进仿真环境，没有优化四种控制律，也没有改实车参数、MCU或系统环境；未启动ROS、设备或新的实车运动。

目的：用已采集的数据约束车辆响应，让离线算法筛选比理想速度积分更接近当前X3在室外硬质地面的表现。已有数据足够完成这一轮校准，不需要为本轮再启动车辆补测。模型仍有未解释误差，不能保证离线排名或厘米数与实车相同。

## 直接运行

在项目根目录执行，不需要启动Web项目、source ROS或连接车辆：

```bash
cd /home/jetson/agri_robot
bash tracking_simulation/run.bash --config tracking_simulation/configs/x3_hard_ground.yaml --controller all
```

新配置默认使用09:52留出实验的0.30 m/s任务、688点路径和第一帧正式跟踪位姿。只从实验读取任务、参考路径和初始位姿/进度；之后每一步的位置由模型和当前算法闭环计算，不使用后面的实测轨迹。执行器从零速初值开始，不还原未知内部机械状态，不重演接近及起点对齐阶段。固定map原点和投影，不把每条轨迹分别归零。

只跑LQR、相同初始条件的理想对照，以及另一组0.50 m/s实验条件：

```bash
bash tracking_simulation/run.bash --config tracking_simulation/configs/x3_hard_ground.yaml --controller lqr

bash tracking_simulation/run.bash --config tracking_simulation/configs/x3_hard_ground.yaml --controller all --ideal --no-animation

bash tracking_simulation/run.bash --config tracking_simulation/configs/x3_hard_ground.yaml \
  --experiment data/experiments/20261127_091746_560120_web_d31cfad4 \
  --controller all --no-animation
```

`--ideal`本轮关闭配置内的模型、定位采样保持及噪声；显式同时传`--model-profile`则拒绝。`--experiment`与`--path-file`互斥。实验路径以命令当前目录为基准，配置中的路径以配置文件目录为基准。

算法参数修改位置为[configs/x3_hard_ground.yaml](configs/x3_hard_ground.yaml)的`tuning`，控制律仍在[four_controler.py](four_controler/four_controler.py)。**没有改默认config.yaml**。实验中的速度、前视、角速度上限、完成容差和搜索窗口优先于YAML的`simulation`同名项；临时速度用`--speed 0.3`或`--speed 0.5`覆盖。可在根级`experiment_overrides`对象内显式覆盖这五项任务参数，CLI优先级最高；输出快照会记住覆盖值，再运行快照不会偷偷恢复原任务速度。改控制器采样周期不在本轮校准范围，v2要求`dt: 0.05`。控制时钟在这一20Hz设计周期附近按训练记录产生波动。

本轮实际比较了0.30与0.50 m/s。行进转向只有这两个速度节点，节点间插值、外部取端点；原地转向主要是±0.30 rad/s短平台。不要把端点钳制理解为范围外已验证。额外噪声仍由YAML控制，当前为0；未用拟合残差冒充独立测得的GNSS白噪声。

不使用归档实验、改用自己的前进参考路径时，在项目根目录运行：

```bash
bash tracking_simulation/run.bash --model-profile tracking_simulation/profiles/x3_hard_ground_v2.json \
  --path-file tracking_simulation/paths/x3_20261127_coverage.json --controller all --speed 0.3
```

此时初始横向/航向偏差、完成容差等取默认config.yaml，不能把结果与采用实测起点的默认新配置混为同一工况。新复制的参考文件在paths内，沿用既有Git忽略规则；原始实验也需随本地数据一起保留，不能假定新克隆自动包含它们。

## 环境改进

1. 输入优先使用真实串口TX帧中的主机写入时间，检查帧结构和校验，按时间保持输入；这是主机发送观察，不是MCU接收确认。早上两组记录没有同期串口数据，回退到无header驱动话题的记录器接收时间，保留其时间不确定性。
2. 使用MGX NED速度及冻结的坐标/杆臂设置形成车体系观测，不以指令或轮速当真值。MGX派生的角速度来自相邻航向的后向差分；辨识比较区间平均角速度，积分使用瞬时模型输出，避免额外算一次平均滞后。
3. 线速度采用增益、等效纯延迟、一阶响应；行进角速度在0.30/0.50 m/s使用不同增益和时间常数。原地转向采用独立等效延迟及两个级联响应，归零有独立衰减参数。普通归零不会瞬间把模型速度变零；定位故障等硬复位清除目标和待执行队列，这是安全抽象，不代表真实机械瞬停。
4. 增加`vy = k × v × ω`的导航等效横向关联，由训练记录确定。它能改善短窗位置预测，但无法分离侧滑、MGX滤波、杆臂或其他误差，不能称实测物理滑移参数。
5. 约10Hz定位采样和20Hz控制时序分开。通过冻结LQR输出的唯一匹配，还原导航样本第一次进入控制输出的时间区间，而非直接用记录器收到消息的时间。区间估计存在非唯一性，1ms计算网格不代表1ms测量精度；交付分布EM达到500次迭代上限，元数据如实标为未收敛至设定容差，不声称找到了唯一真实分布。
6. 定位只交付已经生成的样本，旧帧晚到不能覆盖新帧；超时退出并清除模型残余输入。随机种子固定时，噪声、交付和控制时序可复现。CSV分别记录请求、模型实际速度、源时间、交付时间和来源年龄。

控制时序分布来自LQR实车训练记录，虚拟时钟不随本机每次优化计算的墙钟耗时而改变。它未完整模拟其他算法带来的CPU排队；当前0.30 m/s MPC离线运行的计算耗时最大约71ms，已经超过名义50ms周期，所以“闭环完成、求解收敛”不能等同于实车20Hz实时性通过。耗时统计保留在各算法metrics.json的compute_ms中。

参数见[profiles/x3_hard_ground_v2.json](profiles/x3_hard_ground_v2.json)，v1保留。当前线速度等效增益约0.9248、时间常数约0.411s、延迟0.25s；行进角速度两节点的增益约0.8837/0.8103、时间常数约1.083/0.809s。**这些是对导航观测的等效拟合参数，不是纯MCU延迟或已分离的机械常数。**限幅只是数值边界，本轮没有充分饱和激励来确认机械上限。

## 留出验证结果

开环回放采用同一条实测指令序列；下面的5秒端点误差表示：从一个实测初始位姿出发，用指令和模型自由积分5秒后，与末端MGX位姿的距离。它衡量局部模型一致性，**不是路径跟踪横向误差**，也不是独立真值精度。

|留出实验|角速度预测RMSE，v1→v2 rad/s|5秒端点RMSE，v1→v2 cm|
|---|---:|---:|
|09:52，0.30 m/s|0.0445→0.0370|6.79→4.82|
|08:33，0.50 m/s|0.0637→0.0431|16.72→9.58|
|09:17，0.50 m/s|0.0714→0.0499|14.00→7.97|

线速度预测并非全部改善：09:17的RMSE由0.02102到0.02112 m/s，略有变差；另两组由0.01718到0.01654、0.01983到0.01915 m/s。

自由闭环仅共享实际初始位姿与任务；没有后续轨迹输入。LQR权重取各次冻结实车记录，使用三个时序种子0/1/2：

|留出实验|实测横向RMSE cm|理想模型 cm|v1 cm|v2场景范围 cm|
|---|---:|---:|---:|---:|
|09:52，0.30 m/s|2.482|1.079|1.915|1.891～1.951|
|08:33，0.50 m/s|3.594|0.706|7.106|4.357～4.383|
|09:17，0.50 m/s|5.408|1.066|7.025|4.429～4.449|

三个种子的范围不是统计置信区间。v2在0.50 m/s下显著减少了v1的过度摆动，但无法完整复现两次同参数实车的差异；0.30 m/s仍低估误差约0.53～0.59cm，共同进度下误差曲线差距约1.29～1.31cm，比v1的约1.19cm略差。不能只看总RMSE而认定所有方面改善。

直线/转弯分区、共同0.1m进度采样、逐点误差曲线差距、完成状态和全部参数详见[验证报告](results/x3_campaign_validation_final_20261127/report.md)与同目录`validation.json`，各实验有`response_replay.png`、`closed_loop_comparison.png`和`closed_loop/`逐周期输出。全部原始输入在分析前后核对SHA256；没有回写data中的文件。

## 后续优化与复核

先保持模型和参考路径不变，每次只修改一组控制器参数或控制逻辑。在0.30、0.50 m/s、不同初始位姿和种子下都检查完成状态、横向RMSE/P95/峰值、航向误差、直线/转弯分区、振荡及角速度限幅。比如改变时序种子：

```bash
bash tracking_simulation/run.bash --config tracking_simulation/configs/x3_hard_ground.yaml --controller lqr --seed 1 --no-animation
bash tracking_simulation/run.bash --config tracking_simulation/configs/x3_hard_ground.yaml --controller lqr --seed 2 --speed 0.5 --no-animation
```

每次结果自动创建独立目录，包含`config.yaml`、`model_profile.json`、`experiment_case.json`、`summary.json`、各算法CSV/指标/图片和总对照图；输入与实现指纹随结果保存。输出目录非空会拒绝覆盖。不能仅保存一张最好看的图。算法在多工况中有稳定改善后，再安排少量同条件实车对照。
