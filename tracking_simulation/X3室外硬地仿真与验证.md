# X3室外硬地仿真与验证

本轮按用户确认的“当前X3底盘、室外硬质地面，先匹配已有实验”建立第一版离线筛选模型。它在已有平面仿真上增加实测约束，不要求运行Gazebo、ROS、实车或网页。没有修改实车控制器、系统环境或用户的`config.yaml`默认参数。

## 直接使用

在项目根目录运行，四算法共用同一路径、初始误差、定位采样和地面响应：

```bash
cd /home/jetson/agri_robot
bash tracking_simulation/run.bash --controller all \
  --model-profile tracking_simulation/profiles/x3_hard_ground_v1.json
```

仍可运行理想条件作对照：

```bash
bash tracking_simulation/run.bash --controller all --ideal
```

只筛选LQR或临时改指令速度：

```bash
bash tracking_simulation/run.bash --controller lqr --speed 0.3 \
  --model-profile tracking_simulation/profiles/x3_hard_ground_v1.json
```

三条命令均不启动车辆。结果自动进入`tracking_simulation/results/`，地面模型目录以`ground_`开头。`--no-animation`可跳过GIF。`--model-profile`和`--ideal`不能同时使用；该参数没有接入Gazebo入口。

平面链路为：冻结参考路径 → 控制器的采样定位输入 → v/ω指令 → 增益/限幅 → 等效延迟 → 一阶响应 → 平面位姿积分 → 下一次定位观测。没有把模型位置吸附到参考路径。

地面profile覆盖本轮线/角响应和反馈周期，不叠加YAML中的两个时间常数；位置/航向噪声、初始误差、控制器增益继续使用YAML。当前用户四项噪声/时间常数默认值仍为0，原文件未改。

时间采用同一主机ROS时钟：驱动指令接收时间与MGX主机source_stamp。模型延迟包含归档对齐、设备测量/滤波等影响，不能分解为Jetson→MCU、MCU→电机或MGX各自延迟。

初始3s不评分；指令超过250ms未更新不评分，指令/反馈间断后再剔除3s。只按完全相同source_stamp配对，不用未来定位补缺失帧。两个辨识实验等权，两个验证实验不参与参数优化。`validation.json`同时提供含停车样本和运动样本的速度RMSE，避免只看静止期间的低误差。

## 模型参数与可识别范围

两个通道独立使用：

```text
目标输出 = clip(gain × 指令(t-delay), -limit, limit)
tau × 输出变化率 + 输出 = 目标输出
```

| 通道 | gain | limit | tau | 等效delay |
| --- | ---: | ---: | ---: | ---: |
| 车体线速度 | 0.92894 | 0.63623 m/s | 0.42848 s | 0.075 s |
| 角速度 | 0.76355 | 1.11910 rad/s | 1.00596 s | 0 s |

定位反馈周期取辨识记录的中位数，约0.100 s。辨识数值步长10ms，延迟按25ms网格搜索。命令事件的仿真实现按时间戳排队，延迟前不会提前执行；清零状态时也清掉等待队列，旧命令不会再出现。

这些数值是**等效模型参数**。0.63623m/s不是已经证实的底盘机械上限，角速度delay=0也不说明真实链路没有延迟。角速度limit没有被辨识输入触发，**该限幅值无法充分辨识**，当前支持范围内不会触发它。角速度响应还可能包含MGX测量/航向滤波效应，不能把1.00596s都解释为电机惯性。

没有独立定位真值，不能从这些记录可靠分离GNSS白噪声、轮地侧滑、横移、天线误差和电机动态。因此没有凭拟合残差修改用户噪声参数，也没有声称已经精确模拟麦轮接触。

## 独立回放的结果

先按完整归档指令开环预测速度；预测中不以测量速度反复重置模型状态。与“速度立即且完全执行指令”的模型比较：

| 验证实验 | 线速度RMSE m/s：理想→拟合 | 角速度RMSE rad/s：理想→拟合 |
| --- | ---: | ---: |
| 13:08实验 | 0.07499 → 0.02235 | 0.38494 → 0.10038 |
| 14:10实验 | 0.06969 → 0.01816 | 0.13898 → 0.05873 |

线速度预测误差降低约70%–74%，角速度降低约58%–74%。

另做5秒局部开环位姿校核：每窗仅在起点使用一次MGX位姿，然后按反馈时间步的平均预测速度积分，窗内不再校正位姿，最后与MGX端点比较：

| 验证实验 | 可用窗数 | 端点RMSE m：理想→拟合 |
| --- | ---: | ---: |
| 13:08实验 | 37 | 0.63723 → 0.22338 |
| 14:10实验 | 34 | 0.40315 → 0.11905 |

模型对已有实验的运动响应更接近了，但5秒仍有约12–22cm的端点误差。这是相对MGX的运动学一致性校核，没有独立真值，不是绝对定位精度，也不是跟踪精度通过标准。

完整数据、回放图、各窗误差、来源指纹见[本轮辨识报告](results/x3_ground_validation_final_20261126/report.md)及同目录`validation.json`。每个实验子目录含`replay.csv`、`response_replay.png`和`pose_windows.json`。

## 四算法如何评价

本轮使用当前默认覆盖路径、0.5m/s指令上限、初始横向偏差0.1m和航向偏差5°，保持控制器增益一致，分别做理想执行和地面等效响应的完整闭环对照。

每个算法输出整体横向/航向RMSE、绝对P95、最大误差、完成状态、终点距离、计算耗时及MPC收敛情况，并单列直线/转弯指标。区域按**参考路径**0.5m窗口的航向变化率划分，绝对曲率≥0.1rad/m为转弯，不按车辆是否摆动划分；这是统一的工程评价阈值，不是行业精度标准。

统计包含初始收敛；暂停/对齐/制动阶段保留CSV，但不混入TRACKING精度。未完成、未收敛应先检查，不能只根据某段低RMSE判断优秀。

仿真仍使用`four_controler/four_controler.py`的本地控制律；实车迁移实现在`agri_path_tracking/algorithms.py`。普通前进工况有控制输出一致性测试，但两者不是同一运行程序；仿真没有完整复制实车通信、安全和故障链路。历史四次实验使用的是旧PP，所以本次验证车辆响应，不声称复现新版四算法的历史实车闭环精度。

本轮对照结果见[地面模型四算法报告](results/x3_ground_validated_four_20261126/report.md)和[理想条件报告](results/ideal_ground_comparison_20261126/report.md)。实际横向误差和算法排序会随响应模型改变，不能仅凭理想条件下的厘米级结果选定实车最优算法。

## 重新辨识

使用原四次记录重跑（需本机仍有原始data；只读输入，输出新目录）：

```bash
cd /home/jetson/agri_robot
export TMPDIR="$PWD/tracking_simulation/.cache/tmp"
export MPLCONFIGDIR="$PWD/tracking_simulation/.cache/matplotlib"
agri_backend/.venv/bin/python -B tracking_simulation/calibrate_ground.py
```

使用后续新数据时明确分组：

```bash
agri_backend/.venv/bin/python -B tracking_simulation/calibrate_ground.py \
  --train data/experiments/辨识实验一 data/experiments/辨识实验二 \
  --validate data/experiments/独立验证实验
```

程序拒绝辨识集和验证集重合、非COMPLETED覆盖记录、横移指令、投影不一致、时间倒退、反馈不足以及覆盖已有输出。结果只写入本目录`results/`。生成的`profile.json`不会自动替换当前profile或改变正在运行的实车；检查独立验证报告后，可以通过`--model-profile`明确选择新结果。

`profiles/x3_hard_ground_v1.json`保留本轮参数、训练来源指纹与适用边界，可纳入Git；原始data、paths、results和缓存沿用原忽略规则。新克隆至少需要自行提供米制参考路径；使用已有profile运行不需要复制全部历史data。

软件检查命令：

```bash
agri_backend/.venv/bin/python -B -m pytest \
  tracking_simulation/tests tracking_simulation/gazebo/tests \
  tests/test_tracking_algorithms.py -q \
  --basetemp=tracking_simulation/.cache/pytest_ground
```

本轮软件检查涵盖因果延迟、响应积分、延迟队列清理、合成已知参数辨识、辨识/验证隔离、MGX符号/坐标/杆臂/精确时间配对、源数据只读、原默认配置保留以及原理想/Gazebo软件接口。Gazebo物理模型未做本轮实测标定。

下一阶段应优先收集独立的落地直线加减速、左右定角速度/圆弧和不同速度的响应，核对天线杆臂、测量时间和横向速度。当前验证集没有独立1m/s实验，也未覆盖后退、横移、土壤或不同载荷；这些条件不能直接沿用为已验证模型。本轮没有进行新的实车运动。
